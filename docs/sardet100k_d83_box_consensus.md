# D8.3 同一目标的多个候选框：取共识是否比取赢家更准

接 [D8](sardet100k_d8_box_evidence.md)。D7–D8 的结论是“分不清哪个候选更准”。这一轮换一个问法：**既然选不对，能不能让选谁都无所谓？** 如果同一目标附近几个候选的框误差部分独立，它们的平均应当比赢家自己的框更准。

不训练、不改结构、方法中不使用 GT，只用 CPU。

## 口径

- **方法：** 每个 query 的框替换为同一张图里与它 IoU ≥ 阈值的全部 query（含自己）的框的加权平均。分数、类别和后处理的前 300 规则都不动，所以不影响重复抑制。
  - `uniform`：等权；阈值 .5、.6、.7。
  - `kernel`：权重 exp(−(1 − IoU)² / .025)，阈值 .5。离自己越近的框权重越大。
- **数据：** E000 第 35 轮（D8 那次 CPU 前向的 `queries.npz`）和 E004 第 35 轮（e1_followup 的 `queries.npz`）。E004 的落选候选更多、更准，是对这个假设最有利的情形。
- **评测：** e1_followup 的 COCO 规则，全 val，对未改动的框做配对图像 bootstrap（200 次）。
- **判定线：** 运行前定为全 val AP +0.5 才值得做成网络内的聚合模块。这条线没有先写进文档，结果方向一致、不依赖这条线。
- 代码 `tools/sardet100k/box_consensus_check.py`；服务器输出 `independent_verify_20261106/d9_consensus/`（git `6e305c3`），本地 `analysis_outputs/d9/`。

## 判读

1. **取共识在所有变体、两个运行、所有主要单元格上都更差，而且平均得越多越差。** 假设不成立。
2. **赢家的框平均而言明显好于它周围的候选。** 等权平均让 AP 掉 14 个点，说明落选候选的框整体上更差，它们不是与赢家“可交换”的独立估计。一对一训练的选择在多数目标上是对的。
3. **E004 也一样。** E004 的落选候选是最好的（BP-CB 的 IoU 中位 .82），平均后仍然掉 1.3–10 个点。所以“先用训练把候选变好、再聚合”这条组合路线也没有依据。
4. **这给 +4.7 AP 的上限加了一个限定。** 上限是用真实 IoU 在候选里挑最好的一个得到的。D8.3 说明候选平均而言不如赢家，只是在约两成的目标上碰巧有一个更好（tank 诊断第 14 节：20.9% 的 GT 第一名被超过 ≥ .05 IoU）。而 D7.3、D8 说明没有可部署的信号能认出这两成。这个上限里有多少是“事后挑选”造成的、原理上拿不到的部分，现有数据不能定量，这一点是推断。

## 对“如何解决”的结论

围绕“训练保留哪个 query”这一环，三种思路都已经检验过：

| 思路 | 做法 | 结果 |
|---|---|---|
| 改损失或匹配，让更准的框成为正样本 | E003（Q-MAL）、E004（匹配分类代价 0.5） | AP −0.64；AP 持平、重复框失控 |
| 加通路，让分数读到已有的质量信息 | D7.3（box head）、D8（图像与多尺度特征）的交换上限 | 全 val ΔAP −0.03 到 −0.75，没有一项为正 |
| 让选谁都无所谓：聚合候选的框 | D8.3 | ΔAP −1.2 到 −13.8 |

三者失败的原因是同一个：**一对一去重要求每个目标只有一个高分 query；要把高分从现在的赢家换给更准的那个，必须有东西能认出谁更准；而这个信息在现有的分数、特征和图像结构里都读不出来。** 损失只能改变“希望谁赢”，模块只能改变“信息怎么流”，两者合用也补不上缺失的信息。

所以这一环不再作为方法的切入点。上游的问题仍然成立，也更可处理：让框本身更准（小目标在严格 IoU 下缺少合格框，见 E003 事后分析；E008 去掉 Mosaic 后 bridge +2.67、tank +1.57）。

## 局限

- 聚合用的是固定权重。带学习权重的聚合需要知道哪个邻居更准，又回到同一个信息问题，这里没有单独检验。
- 没有检验端到端训练的“在最终框上重新取特征再打分”的结构。D8 的线性探针不支持它，但不能排除。
- 单种子、单个检查点。
