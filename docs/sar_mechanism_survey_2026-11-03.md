# SAR-AIRcraft 涨点机制调研：文献、SAR 特性与本仓库诊断

日期：2026-11-03。前提：主协议为 [B-v1](sar_protocol_b.md)（trainval 训练、统一尺度 1024、132 轮固定日程），baseline 在跑；
用户判断 DEIM 与 D-FINE 差别不大，以 DEIM-D-FINE-M 为 baseline。
文献来源：`C:\project\文献\2025-2026_跨分辨率相似飞机\`（9 篇全文 + PGD + SEFFNet + 数据集论文），以及本次补充检索。
已有导航笔记 `阅读导航与方法判断.md` 侧重"跨分辨率相似型号"，本文侧重"什么机制能在我们的 baseline 上真正涨点"。

## 0. 结论

1. **我们缺的不是网络容量，是信息。** 本仓库在 640 下试过 20 多个特征 / 注意力 / 频域 / 校准 / 原型 / 类别查询模块，
   test 上基本都在单种子噪声范围（±1.5 AP）以内。文献里也一样：通用特征模块在 YOLO 上只有 +1–2；
   而真正加入新信息的方法，增益大一个量级——结构掩码 MTSGL 识别 +6.8%，部件 BU-SIP +13.5%，关键点几何 +3%。
2. 按预期收益排序，推荐三条：
   - **A. 斑点重采样增强**：针对重叠切片中的斑点完全相同，成本最低，最先做；
   - **B. 语义散射结构（关键点）监督 + 结构引导的型号判别**：论文主方法，新意和上限都最高，但要先解决标注来源；
   - **C. SAR 域检测预训练**：用 SARDet-100K 做中间预训练，作为所有方法共用的初始化 trick，算力成本最高。
   **更新（同日）：B、C 不采纳。** S3U 的代码与数据要等论文录用后才公开，自标不现实；C 算力成本过高。
   保留 A，新的替代方向（不需要新标注、新数据，侧重 DETR query）见第 6 节。
3. 不再推荐的方向：继续加频域 / 注意力 / 特征融合模块（REM 类、稀疏卷积、GIFD 类颈部），以及 ASC 参数化图网络。
4. **对增益上限的现实预期。** B 协议下 test 有 77% 的目标在 trainval 里出现过，型号错误主要来自剩下 23% 没见过的飞机。
   一个机制即使把没见过飞机的识别率提高 10 个点，总体 AP50 也只多 2 个点左右。所以单个机制 +1–3 AP 是合理的目标；
   每个实验都应同时报告见过 / 没见过子集（内部诊断）。

## 1. 已知瓶颈（来自本仓库诊断，不再重复做）

| # | 瓶颈 | 证据 | 出处 |
|---|---|---|---|
| W1 | 没见过的飞机型号识别差 | A 口径 test：见过的定位且判对约 0.89，没见过约 0.22；型号正确率 0.94 对 0.41 | [型号混淆诊断](sar_confusion_cues_diagnosis.md) |
| W2 | 主要混淆集中在少数几对 | 737→787 占 test 737 的 19.8%，其后是 A220→other、A220→ARJ21、ARJ21→737；A220、other 判错时真类多在第 2 名 | 同上 |
| W3 | 数据冗余大，有效样本少 | train 只有 1051 架不同的飞机（每架中位数出现 10 次，最多 45 次）；重叠切片之间像素级相同，斑点也相同 | 同上 |
| W4 | 严格 IoU 下的定位误差 | AP 与 AP50 相差约 20 个点；早期诊断显示改进空间主要在小目标边缘定位 | [定位诊断](localization_diagnosis_2026-10-24.md) |
| W5 | 标签有歧义 | other 类内部是多种机型的混合；val、test 中各有 1 组重复切片同时混有 787 与 other 标签 | 型号混淆诊断 |

SAR 本身的特性（与光学不同，决定了哪些机制合理）：

- **斑点是乘性噪声**：实测 ENL≈4.6。同一目标在不同的斑点实现下应判为同一型号。
- **离散强散射**：发动机腔体、翼身结合处、尾翼是强散射点，机身蒙皮反而可能很弱。
- **方位敏感**：同一部件随朝向可能"物理存在但几乎不可见"（S3U 的可见性属性）。
- **侧视几何**：阴影与叠掩方向固定。翻转会改变它们的方向，S3U 因此禁止翻转与缩放。
- **单一分辨率**：数据集全是 1 m 分辨率；B 协议的统一画布让像素尺寸与米成固定比例（0.683 px/m）。

## 3. 文献的共性与缺口

1. **增益大小与"新增信息量"相关，与"模块复杂度"无关。** 加入结构掩码、部件、关键点的方法增益最大；
   通用模块在 YOLO 基线上一般只有 +1–2。这和本仓库 20 多个模块的结果一致。
2. **语义结构停在分类或姿态估计，没有进入检测器的型号判别。** S3U 有最好的 SAR 飞机结构定义，下游却只做了朝向估计；
   MTSGL、BU-SIP、关键点几何都是切片分类。**检测器中的结构引导型号判别是空白**，也正是我们的 W1/W2。
3. **检测器里的物理先验都是无序、不分类别的。** PGD 的散射点掩码、SEFFNet 的结构张量掩码、SFG-Net 的散射中心都是这样；
   而 S3U 恰好论证了无序散射中心对飞机不稳定，需要部件语义和可见性。这是 PGD 的未完善机制，也是我们可以补的点。
4. **几乎全部建立在 YOLO 上。** 唯一的 DETR 工作是 BHCL，增益小。DETR 的 query 天然对应"一个实例"，
   比密集检测器更适合挂实例级的结构预测（关键点、部件），这是我们换基线后的结构性优势。
5. **数据侧几乎没人做。** 斑点类增强只在分类文献出现过，检测上找不到实测增益；没有工作处理切片冗余；
   S3U 明确禁止翻转与缩放（会破坏拓扑和散射方向），与我们保留水平翻转的做法相反，值得做一次消融。

## 4. 候选机制（按优先级）

### A. 斑点重采样增强（数据侧，SAR 特性）— 最先做

- **动机**：W3。重叠切片之间连斑点都完全相同，模型可以通过记住斑点纹理来识别"见过的飞机"。
  W1 说明它确实在记忆。光度抖动对 SAR 没有物理意义，B 协议已经关掉；斑点重采样是物理上正确的"光度增强"。
- **做法**：在强度域估计确定分量 R（例如 7×7 局部均值或 Lee 滤波），按乘性模型 I' = R · s 重新生成斑点，
  其中 s ~ Gamma(L, 1/L)，L≈4.6 取实测值，然后换回存储的幅度域。概率 0.5，只在有增强的阶段使用（与 mixup 相同的区间）。
  先在 CPU 上核对生成图像的 ENL 和直方图与原图一致；8 bit 量化与可能的非线性拉伸是主要不确定点。
- **文献改进点**：检测文献中没有斑点增强的实测增益；我们针对的是切片冗余这一数据集特有的问题。
- **开销**：只在训练时，推理零开销；1 次 B 协议运行（约 6 小时）。
- **证伪**：没见过子集的型号正确率要上升。如果只有见过子集下降而没见过子集不变，说明它只是削弱了记忆，不采用。
- **扩展（如果有效）**：同一图像两个不同斑点实现，对匹配到同一 GT 的 query 加分类一致性损失（斑点不变性），可作为第二个贡献。

### B. 语义散射结构监督 + 结构引导的型号判别（论文主方法）

**标注来源**（必须先定，决定可行性）：

1. **KP-SAR-Aircraft-1.0**（S3U，2990 个样本、7 类、高分三号 1 m）：论文称将在 https://github.com/YYF121/S3U-SAR 公开，
   本次没找到下载。可以联系作者。拿到后用 `tools/check_split_overlap.py` 的切片匹配器把样本映射回 SAR-AIRcraft 实例，
   **只保留源图在 trainval 中的实例**——这个数据集很可能也含有 test 切片，用它们就是泄漏。
2. **自己标注，并利用切片冗余传播**：trainval 中不同的飞机约 1150 架（train 1051 + val 中 train 没有的约 96 架）。
   每架标 4–6 个点（机头、机尾、两翼尖，可选两发动机）和可见性，约 10 小时；再按匹配关系，以框归一化坐标复制到
   全部 13,513 个实例。**数据集的冗余在这里反而降低了标注成本**，这是别人没有利用过的一点。
3. 没有标注时的退路：BU-SIP 式无监督部件（每个 query 带 K 个部件子查询，加正交性与覆盖损失）。新意和预期都更低。

**机制**（在 DEIM-D-FINE 的 decoder 上，逐步加）：

- **B1 关键点辅助头**：每个 decoder 层的 query 预测 K 个关键点（相对框归一化的偏移）与可见性。
  只对匈牙利匹配上的 query 和去噪 query 计算损失：S3U 式按可见性加权的指数 L1，加刚体拓扑边长损失；
  可见性 = 0 的点不参与。头很小。
- **B2 关键点锚定采样**：最后 1–2 个 decoder 层，在可变形注意力的参考点中加入预测的关键点，
  让分类特征去看发动机、尾翼这些部位（OST-DA 是自由学习的拓扑头，没有结构监督，失败了，正好作对照）。
- **B3 归一化几何描述子**：从预测的关键点计算与旋转、尺度无关的量，包括翼展 / 机长、发动机纵向位置 / 机长、
  发动机间距 / 翼展、尾翼宽度 / 翼展。由于 B 协议是统一尺度，再加上以米为单位的机长与翼展
  （数据集固定 1 m 分辨率时才成立，论文中说明）。经 MLP 后加到分类分支。
  737（约 39.5 m / 35.9 m）与 787（约 57 m / 60 m）在物理尺寸上本应很好区分，A220 与 ARJ21 的发动机位置不同
  （ARJ21 是尾吊发动机），这些正是 W2 中主要混淆对之间的差异。
- **对文献的改进**：S3U 的结构进入检测和型号判别；PGD 的无序先验换成语义有序的结构；MTSGL 的人工模板换成关键点；
  关键点几何论文的模板匹配换成可学习描述子；全部在实时 DETR 上，推理只多一个小头。
- **证伪**：B1 用打乱的关键点或框导出的伪关键点（框中心与四边中点）作对照，结构标签必须明显更好；
  逐类看 737、787、A220、ARJ21 的 AP50 与混淆矩阵；看没见过子集。
- **风险**：标注成本；关键点在低可见性时噪声大（S3U 的关键点 AP 也只有 59）；B3 要求关键点相当准。

### C. SAR 域检测预训练（所有方法共用的初始化 trick）

- **动机**：W1、W3。COCO 初始化之外，SARDet-100K 提供其他传感器的飞机（SADD 是 TerraSAR-X，MSAR 是海丝一号），
  能增加"不同的飞机"的数量，这是唯一能直接扩充 1051 架这个上限的办法。
- **泄漏检查**：SARDet-100K 包含 SAR-AIRcraft，并保留了官方划分（512 切片、重叠 200）。
  它的 train 只含 SAR-AIRcraft train 的切片；B 协议本来就用 trainval 训练，test 不会被直接看到。
  仍需用切片匹配器确认 SARDet-100K train 中没有与 SAR-AIRcraft test 重合的切片（超出官方 val/test 本身重叠的部分）。
  不使用 SARATR-X-v2 等预训练集中含 SAR-AIRcraft 而划分不明的公开权重。
- **做法**：DEIM-D-FINE-M 在 SARDet-100K train 上训练（COCO 初始化，约 36–60 轮；已有的 S 规模 120 轮运行可以参考日程），
  再用 `-t` 初始化 SAR-AIRcraft，7 个类别头由 aircraft 一行初始化（沿用 `tools/init_head_from_coco_class.py` 的思路）。
- **开销**：最高（9.4 万张图）；只需做一次，baseline 与所有方法共用。
- **定位**：作为协议的一部分或单独消融，不作为方法贡献。

### D–F. 低优先级（便宜，可作为补充）

| # | 机制 | 依据 | 为什么排后面 |
|---|---|---|---|
| D | 分类 / 定位 query 解耦（BHCL） | DETR 上 +0.4–1.2 AP | 本仓库的 BCCQ（类别查询）−2.9 AP；改动大，收益小 |
| E | 噪声鲁棒分类损失（SFEF 的 NR 损失，按误差大小降低离群样本的权重） | YOLOv5 上 AP50 +0.5、AP50:95 +1.3 | trainval 中标签冲突很少（val 只有 1 组）；收益可能在噪声内 |
| F | 散射先验 query 选择（PGD 式无序先验，见 [D-FINE 方案](sar_dfine_paper_plan_2026-11-03.md) 的 M1/M2） | PGD、SEFFNet | 被 B 覆盖且更弱；只在 B 的标注无法解决时作为退路 |
| — | 去掉水平翻转（S3U 的增强原则） | 翻转改变阴影 / 叠掩方向 | 单项消融，1 次运行即可 |

## 6. B、C 不采纳之后：不需要新标注与新数据的方向（侧重 DETR query）

### 6.1 以往 query 侧改动为什么都没涨

| 模块 | 对 query 做了什么 | 结果 |
|---|---|---|
| MPQ | 最后一层 query 上加原型辅助分类 | 102 轮 val 64.36 对 64.51，test 无收益 |
| SCS | query 回归 28 维散射描述 + 混淆对间隔 | val 64.0（低于 baseline） |
| SLQC | 按预测框在 P3/P4 取局部 token，给分类加残差 | val 63.4 |
| MDCC | 分类头改为余弦 + 类间正交 | val 64.0 |
| BCCQ | 每个实例 7 个类别查询、子带路由、型号/质量分解 | test −2.9 AP |

共同点：都在**给 query 增加分类容量或新的类别语义**，默认"信息在特征里，只是没读好"。
诊断说的是另一回事：A 口径 test 上，没见过的飞机连"任意类别、score≥0.3、IoU≥0.5"的定位率也只有 0.54（见过的 0.94），
型号正确率 0.41 对 0.94。模型是在**记忆实例**，不只是型号读不准，没见过的飞机连检出都差。
所以 query 侧的改动应该改**训练信号**（query 必须对什么不变、每个重复实例算几次），而不是再加头。

顺带排除一项：trainval 每图 GT 均值 3.8、最多 30（`C:\project\实验记录\sar_characteristics\…\images.csv`），
DEIM 的去噪组数 `100 // 批内最大 GT` 在每卡 6 张时平均约 14 组，去噪查询并不缺；300 个 query 对每图中位数 3 个目标也足够。
query 数量、去噪组数都不是瓶颈。

### 6.2 候选（按优先级）

**Q1. 去噪查询锚定的斑点一致性（建在 A 上，建议作为主方法）**

- 同一批图像生成两个视图：几何、mixup、多尺度完全相同，只有斑点实现不同（A 的生成器，各自独立采样）。
  实现上把斑点重采样放在 collate 中 mixup 之后、多尺度缩放之前，对复制的批次分别施加，两视图的几何天然一致。
- **DETR 特有的对应关系**：两视图共用同一份去噪查询（同一次标签/框加噪的结果），第 i 个去噪查询在两边严格对应，不需要匹配；
  普通查询用匈牙利匹配到同一 GT 的那一对。
- 损失：对应查询的型号分布对称 KL（7 类 softmax，温度固定），加 FDR 四条边分布的 KL；各以另一视图为 detach 的目标。
  权重事先固定（如 1.0），不在 test 上调。
- 与 A 的区别：A 只是让同一飞机在不同 epoch 看到不同斑点；Q1 在同一步里直接惩罚"预测随斑点改变"。
  文献中斑点一致性只出现在切片分类；DETR 上的跨视图一致性多是半监督师生框架，用去噪查询作免匹配的对应锚点，未见先例。
- 开销：推理零开销。训练每卡 3 张 × 2 视图，显存与 baseline 相同，同样 132 轮时迭代数翻倍，约 12 小时。
  公平性在论文中说明：同轮数比较，另给 A 单独一行作对照。
- 证伪与诊断：相对 A 单独，没见过子集的定位率和型号正确率要上升；另报一个不需要标签的量——
  **斑点翻转率**：test 图像换两次斑点实现，同一框型号改变的比例。Q1 应明显降低它，否则机制不成立。
- 注意：斑点要在工作分辨率上模拟。B 协议先补边到 1500 再缩到 1024（0.683），斑点已被平均，ENL 会高于原图的 4.6；
  CPU 检查时在 1024 图上估计 L，按估计值生成。

**Q2. 冗余感知的实例加权**

- 用现有匹配器（`tools/check_split_overlap.py` 的 24×24 相关、阈值 0.9）只在 trainval 内部分组，得到每个 GT 所属"同一架飞机"组的大小 n。
  权重 w = n^(−0.5)，按 trainval 全体实例归一到均值 1，存为 annotation id → 权重的旁路 JSON，不改原标注。
- 在 criterion 中给匹配上的普通查询与去噪查询的分类（MAL）、框（L1/GIoU）与 FDR/DDF 损失乘上 w；未匹配的负样本不变。
  mixup 时随标签一起拼接。
- 动机：出现 45 次的飞机拿到 45 倍梯度，单次出现的飞机几乎被淹没，训练偏向背熟高频重复。
  这是实例级的"类别平衡"，针对的是重叠切片数据集（多数 SAR 数据集都是切片）这一共性，文献中没有处理过。
- 开销：训练与推理都零开销；CPU 预计算几分钟。
- 风险：test 77% 的目标见过，且多来自高频重复的飞机，降权可能拉低见过子集。证伪：没见过子集上升、见过子集下降不超过 1。
  也可改为图像级采样权重（对重复度高的图降采样），两者择一。

**Q3. 混淆感知的去噪标签噪声（Q1 的小组件，可并入同一运行）**

- DEIM 去噪的标签噪声目前是 7 类均匀随机（`engine/deim/denoising.py`，`label_noise_ratio` 0.5 的一半位置被替换）。
  改为按事先固定的物理分组采样：窄体 {A220、A320/321、ARJ21、737}、宽体 {A330、787}、other；例如 80% 替换为组内其他类。
- 正样本去噪查询的目标仍是真实类别，于是 decoder 被迫在"给错的近似类别提示"下按视觉证据纠正，正好训练主要混淆对。
- 分组按机型物理属性定，不用 test 的混淆矩阵。改动一行加一个开关，零开销；预期 ≤0.5 AP，作为组件消融。

**Q4. 解耦的"是不是飞机"置信度（先做零训练诊断）**

- 假设：每类独立 sigmoid 下，型号不确定时置信度被分散，没见过的飞机最高分达不到 0.3，这也许是定位率 0.54 的一部分原因。
- 先在 B baseline 的 `final.pth` 上做诊断，不训练：把 7 类合并成 1 类算类别无关 AP50，按见过 / 没见过子集分别统计。
  - 类别无关的召回在没见过子集上也低：问题在目标性本身，属于 Q1/Q2 的范围，Q4 放弃；
  - 类别无关召回高而分类别 AP 低：再训练一个共享的飞机目标性分数，score_c = obj × softmax 型号概率。
- BCCQ 里含有类似的分解，但和大量其他改动绑在一起，单独的小版本没测过。诊断只看现象，不在 test 上调任何参数。

**Q5. 散射点吸引的可变形采样（只在诊断支持时做）**

- 先诊断：导出 baseline 最后一层匹配查询的采样点与注意力权重，统计权重落在框内 CFAR 强散射点 r 像素内的比例，与框内随机点比较。
  如果已经很高，说明 decoder 本来就在看强散射，这个方向放弃。
- 比例低时，对匹配查询的最后 2 层加训练期损失：注意力加权的"采样点到最近强散射点的距离 / 框尺寸"。推理零开销。
- 这是 PGD、SEFFNet 特征级散射先验在 DETR 采样上的迁移；但本仓库特征级物理先验（PGD-REM、SPI、SDCP）都 ≤+0.6，
  且 S3U 指出无序强散射点随方位不稳定，所以排在最后。

**Q6. 去掉水平翻转**：单项消融，1 次运行（原 D–F 表中已列）。

不推荐：再给 query 加类别语义头（上表 5 个都失败）；query 间关系或场景一致性（737 的错误按图成簇，关系建模会把错误一起传播）；
改 query 数量或去噪组数（上面已排除）。

### 6.3 论文主线与预期

两个贡献都指向同一个诊断出的失败模式——重叠切片加相同斑点导致的实例记忆：
Q1 让 query 对斑点不变（DETR 特有的去噪锚定），Q2 让每架飞机只算一次；两者都不增加推理开销。
再加上见过 / 没见过拆分与斑点翻转率作为分析贡献。新意属中等，说服力主要来自诊断与机制的对应、多种子下的一致增益。

叠加合计约 +1.5–3，与第 0 节的上限估计一致。没有一项有训练证据，全部待验证。

## 7. 把"文献缺口"与"缺信息"合起来：无标注的结构与成像一致性机制

### 7.1 思路

不加数据、不加标注时，信息只能从两处来：**先验替代数据**（对称、刚体旋转、成像几何这些物理事实，
等价于"免费的样本"），以及**去掉虚假信息**（相同斑点、不一致的照射方向，模型会拿它们当捷径）。
对应第 3 节的四个缺口：

| 缺口 | 不用关键点标注时怎么补 |
|---|---|
| 语义结构没进入型号判别 | 用飞机的**镜像对称轴**定义机体坐标系，query 在机体坐标系里采样——第 k 个采样点总落在同一个机体部位，特征变成"有序部件"的 |
| 物理先验无序、与类别无关 | 先验从"框内强散射点集合"换成"每个实例的对称轴"，是实例级、有方向的结构量 |
| 几乎全是 YOLO | 对称轴挂在 query 上预测，再旋转该 query 的可变形采样模式，只有逐实例 query 的检测器能这样做 |
| 数据侧没人做 | 照射方向一致的翻转、斑点重采样（A）、去噪锚定的斑点一致性（Q1）、冗余降权（Q2） |

### 7.2 新证据：没见过的飞机，朝向越少见判得越错

用已有 `targets.csv`（A 口径 102 轮 baseline，强散射像素主轴，只取轴比 ≥1.5）算的，本地 CPU、没有新运行：

- **train 的停放朝向高度集中。** 按"不同的飞机"去重后 789 架，主轴在 75–105° 的占 40%（以图像 x 轴为 0°，15° 一档）。
- **test 没见过的飞机（定位上的 667 个 GT）**：按"本类在 train 中 ±10° 内的同朝向比例"分三档，
  型号正确率从少见到常见为 **0.275 / 0.455 / 0.552**，单调上升。
  val 只有 175 个，三档为 0.138 / 0.776 / 0.356，噪声太大，不作结论。
- 见过的飞机三档都在 0.93–0.96，与朝向无关（背下来了）。

**局限**：
- 主轴来自亮像素的二阶矩，分不清机身和机翼（十字形飞机常被丢弃，A330 全部丢弃）；
- test 有效飞机数少；
- 这是相关性，不能证明朝向是原因。

但方向与"模型没有学到旋转不变的结构，只记住了常见朝向下的外观"一致。
COCO 光学预训练与 DETR 的可变形采样都不具备旋转等变性；OST-DA 学了一个 θ 但**没有监督**，结果在噪声内（58 轮 test +0.64 / −0.20）。

### 7.3 机制

**S1. 对称轴监督的机体坐标系 query（Body-Frame Query，建议作为主方法）**

- **伪标签（离线，只用 trainval，CPU）**：对每个 GT 裁剪，在对数幅度、轻度斑点平滑后的图上，
  以框中心为轴心、θ 每 2° 一档做镜像翻转，取与原图归一化相关最大的 θ 作为对称轴，峰值减中位数作为置信度。
  飞机只有一条镜像轴（机身），翼展方向不是对称轴（机头、机尾不同），所以比二阶矩主轴更能区分机身和机翼，
  十字形也能判。框中心一般不在机身轴上（后掠翼、旋转），所以镜像线过亮度质心（对称目标的质心在对称轴上），并在垂直方向做小范围平移搜索。
  质检用框抖动后轴是否稳定、与二阶矩主轴的关系和目视。重叠切片的重复是像素级相同的，组内一致率没有检验意义，不用。
- **预测**：每个 decoder 层的 query 预测单位向量 u；损失只约束倍角 (cos2θ, sin2θ)，按伪标签置信度加权，
  作用于匹配的普通查询和去噪查询。机头朝向的正负号不监督，由网络自己选一致的一侧——不需要机头标注。
- **机体坐标系采样**：最后 1–2 层的可变形注意力里，偏移在机体坐标系下生成，再用 R(u) 旋转到图像坐标。
  直接复用 OST-DA v2 的十字对称采样实现（`engine/deim/symmetric_topology_attention.py`），区别只是 θ 换成有监督的 u。
  同一编号的采样点因此始终落在"机身前段 / 翼尖 / 尾部"这类固定部位，分类特征是有序部件特征。
- **它补的是哪种信息**：刚体旋转先验。train 只有约 1051 架、朝向集中，把外观对齐到机体坐标系，
  相当于让每架飞机在所有朝向下都"见过"。7.2 的预测因此很具体：**少见朝向那一档的改善应该最大**。
- **对照**：OST-DA v2（同结构、无监督 θ）；θ 用二阶矩主轴（无序先验）；θ 随机。三者都应明显弱于 S1，否则机制不成立。
- **开销**：一个 2 维小头，推理基本不变；训练 1 次 B 协议运行。
- **风险**：SAR 下对称性被叠掩、阴影、方位相关的强散射破坏（一侧机翼可能更亮），伪轴可能偏；
  必须先过 CPU 质检（重复组一致率、抽 50 张目视）再上 GPU。

**S2. 照射方向一致的翻转（数据侧，1 次消融）**

- B 协议目前用水平翻转。SAR 侧视成像，阴影、叠掩朝固定的距离向；如果数据集图像的距离向是水平的，
  水平翻转就造出了"雷达从另一侧照射"的不真实样本，而沿方位向（竖直）翻转在物理上成立（飞机本身镜像对称）。
- **CPU 先查**：对每个 GT 取框外四个方向的条带，比较左右、上下的平均强度（阴影侧更暗），按图统计哪一侧暗。
  - 全数据集一致朝某一侧：把水平翻转换成竖直翻转；
  - 按图不同（升降轨混合）：先按估计的照射方向把图像翻到同一侧（图像级规范化，测试同样处理），再只做方位向翻转；
  - 没有一致的暗侧：S2 放弃。
- 好处有两层：去掉不物理的样本；同时让阴影方向固定，decoder 可以稳定地利用阴影
  （阴影长度反映垂尾高度，787 约 17 m、737 约 12.5 m，这是尺寸诊断里框大小给不出的线索）。
- 竖直翻转还把 θ 映射成 −θ，在物理上合法地扩充了 7.2 中集中的朝向分布，与 S1 互补。

**S3. 斑点与冗余**：沿用 A、Q1（去噪锚定的斑点一致性）、Q2（冗余降权），见第 4、6 节。它们去掉的是虚假信息。

### 7.4 合在一起的论文主线

**"物理一致的 DETR"**：结构一致（S1，对称轴定义的机体坐标系 query）＋ 成像一致（S2 照射方向、A/Q1 斑点）。
每一项都对应一个可检验的诊断量：
- S1：少见朝向档的型号正确率；
- S2：阴影侧统计；
- Q1：斑点翻转率；
- 全部：见过 / 没见过子集。

全部不需要新标注和外部数据，推理开销可忽略；S1 是对 OST-DA（本仓库已有的负结果）的直接改进，消融对照现成。

### 7.5 先做的 CPU 检查（不占 GPU，baseline 跑的同时就能做）

| 检查 | 通过条件 | 不通过 |
|---|---|---|
| 对称轴伪标签：置信度（margin）分布、框抖动 ±10% 后的轴变化、与主轴的关系、目视拼图 | 高置信样本过半，高置信样本抖动后 ≤10° 的比例高，目视轴在机身上 | S1 改用二阶矩主轴作弱监督或放弃 |
| 照射方向：框外四向条带暗侧统计 | 有一致的暗侧（全局或按图） | S2 放弃 |
| 1024 工作分辨率下的 ENL（给 A/Q1） | 得到 L 估计 | — |

GPU 顺序：B + S2（6 小时，最便宜）→ B + A → B + S1 → 有效项组合 + Q1 → 多种子。

### 7.6 检查工具与服务器命令

工具 `tools/check_structure_priors.py`。它只读原始 COCO 标注和原图，只用 CPU，不推理，不改标注。输出到一个新目录；目录已存在时报错，不会覆盖。

1. **对称轴**：
   - 对每个 GT，在 1.2 倍框的窗口内取对数幅度，做 3×3 平滑，再缩放到 48×48。
   - 每 2° 一个候选角度；镜像线过亮度质心，并在垂直方向平移 ±3 px 搜索。
   - 输出峰值相关、margin（峰值 − 中位数）、与垂直方向的差、框抖动 4 次后的最大轴变化，以及与亮像素主轴的夹角。
   - `sheets/` 中保存随机、高置信、低置信三组拼图：红线是对称轴，蓝线是主轴。
2. **照射方向**：
   - 对每个 GT 框，取外侧四个方向、深度 0.5 倍框边长的条带，计算中位数；条带内落在任何 GT 框里的像素都排除。
   - 输出 lr 与 tb 的对数比，以及逐图中位数与全局多数同号的比例。
   - 用同尺寸的随机背景框作对照。
3. **ENL**：分别计算原图与 B 协议工作分辨率（补边到 1500 后缩放到 1024）下的值。

### 7.7 检查结果与决定（2026-11-04，新服务器真实数据）

结果目录：`/root/zxy/experiments/diagnostics/structure_priors_20261104_112711`（revision `aef3c03`），全部 16463 个目标，只用 CPU。

**S1：不通过，暂停。**

| 条件 | 结果 | 判定 |
|---|---|---|
| 高置信（margin ≥ 0.15）过半 | train 0.57、val 0.63、test 0.64 | 通过 |
| 高置信目标抖动后轴变化 ≤10° 的比例高 | train 0.41、val 0.56、test 0.57，与全部目标（0.41、0.50、0.49）几乎相同 | **不通过** |
| 目视轴在机身上 | 拼图里部分明显在机身上，也有不少无法判断或明显偏离；没有真值，不算通过 | 未确认 |

- **margin 筛不出可靠标签**：train 上 margin [0.3, 0.5) 的 ≤10° 比例是 0.30，[0.5, ∞) 是 0.40，都不高于 [0.05, 0.3) 的约 0.47。原设计的"按置信度加权"因此不成立。
- **最需要提升的 ARJ21 伪标签最差**：train+val 的 margin 中位数 0.14，≥0.3 的只占 7%（其他类 16%–36%）。
- 按 §7.5，退路是二阶矩主轴，但 §7.3 本来把它当作应当更弱的对照，所以不改用。
- 可能的抢救：改用"抖动稳定"本身作筛选（约 45% 的目标）。稳定不等于正确，还需要另行验证；只有错误拆解显示没见过目标的型号混淆是主要损失时才值得做。

**S2：不做，保留水平翻转。**

- **没有全局一致的暗侧**：train 非零样本中左侧更暗占 0.427（随机背景框 0.463），上侧 0.447（背景 0.506）。
- **图内有方向信号**：train 中 ≥5 个非零目标的图，留一法同号率 lr 0.698（背景 0.514）、tb 0.570（背景 0.524）。这可能是各图照射方向不同，但也可能是停机坪布局，没有区分。
- **train 与 val/test 方向不同**：左侧更暗在 train 0.427，val 0.709，test 0.684（背景约 0.50）。
- **S2 的前提不成立**：两种方向在真实数据里都有，水平翻转产生的不算"不真实样本"。而按图规范化在测试时需要先知道方向，现有估计依赖 GT 框，目标少的图也估不准。
- 这里只用于决定不改协议；test 的方向统计不用于选择增强。

**ENL：** 工作分辨率 train p10/p50/p90 = 3.91 / 6.85 / 22.31（原图 3.60 / 4.62 / 19.38）。A 的 L 不应沿用 4.6；各图差异大，单一 L≈6.85 会给平滑图加过多噪声，实现时按图估计。

**对论文主线的影响：** §7.4 的"结构一致"一半暂不成立。当前候选清单为 REM、CLCR-Lite、A、Q1，Q2 备选；主方法要等 B-v1 错误拆解（`docs/sar_protocol_b.md` §3.2）后再定。

**错误拆解结果（`docs/sar_protocol_b.md` §1.2）：** 没见过目标的 AP50 28.85、定位率 0.484，损失主要是检不出，不是型号判错。Q4 放弃；S1 的抢救条件（型号混淆为主）不成立，不再做。

**漏检原因（同上）：** 85% 的漏检已有准确的框，但分数极低（中位数 0.009），且按架次全有或全无。因此散射引导的 query 选择（M2）、采样（Q5）和校准都不对症，问题在于模型对没见过的飞机没有置信。方向是改训练信号：A（斑点）、Q1（一致性）、Q2（重复降权）；另增候选 R（竖直翻转与 90° 旋转，框保持紧贴、尺度不变，针对朝向集中）。
