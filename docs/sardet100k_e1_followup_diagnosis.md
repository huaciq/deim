# E1 后续诊断：AP50 下降的来源、末层 Query 排序与跨层监督

E1 = E004（`match_cls05`，matcher 分类代价 2 → 0.5，其余与 E000 相同）。本阶段不训练、不改结构、不加模块。

## 口径

- **权重：** 两者都用各自第 35 轮 `best_stg2` 的 EMA 权重。
  - E000：`deim_m_sardet100k_deim_hgnetv2_m_sardet100k_36e_b32_nozoom_nocrop_seed0_20261105_125147_N2zAJh`
  - E1：`deim_m_sardet100k_deim_hgnetv2_m_sardet100k_match_cls05_36e_b32_seed0_20261108_195504_7ewHSg`
- **匹配器：** 各用各的（E000 cost_class 2，E1 0.5）。
- **数据：** SARDet-100K val 全部 10,492 张，640×640 输入。没有读 test。
- **检测框重建：** 从末层 300 个 query 重建，规则与配置的后处理一致（sigmoid 后在 300×6 上取前 300）。因此每个检测框都能对应回它的 query，进而对应回训练时的正负分配。
- **评测：** 按 COCO 规则重写（area all、每图每类前 100、101 个召回点）。
  - 在合成数据上与 COCOeval 一致。
  - 在真实数据上复现了训练日志：E000 AP50 93.145 / AP75 70.262（日志 93.15 / 70.265）；E1 87.996 / 73.203（日志 87.995 / 73.203）。
- **检测框类型**（IoU .5，按以下顺序判定，只统计 COCO 实际评测的检测框）：
  - TP：被匹配上；
  - 重复 FP：未匹配，但与同类 GT 的 IoU ≥ .5；
  - 类别混淆：与异类 GT 的 IoU ≥ .5；
  - 定位 FP：与同类 GT 的最大 IoU 在 [.1, .5)；
  - 背景 FP：其余。
- **GT 候选**（沿用 survey 规则）：在同类 GT 中以该 GT 为最大 IoU 对象、且 IoU ≥ .1 的 query。
  - top = 该类分数最高的候选；best = IoU 最高的候选。
- **BP-CB query（框正向、分类背景）：** 在 union set 中（末层的 box / FGL / DDF 损失把它拉向 union GT），但不是末层 matcher 的匹配结果（末层 MAL 对所有类别的目标都是 0）。
  - 即 `DEIMCriterion` 训练统计里的 `boxpos_clsbg_dec4`；union 规则用 `_get_go_indices`，与训练一致。
- **代码与输出：**
  - 代码：`tools/sardet100k/e1_followup.py`（collect / analyse / plot）。
  - 服务器输出：`independent_verify_20261106/followup_E000`、`followup_E004`、`followup_compare`。
  - 本地输出：`analysis_outputs/e1_followup/`，包括 `followup.json`、`figures/`、`cases/`。

### 1.5 AP50 下降的定量归因（oracle，仅用于诊断）

| 情形 | E000 AP50 | E1 AP50 | Δ |
|---|---:|---:|---:|
| 原始 | 93.15 | 88.00 | −5.15 |
| 去掉重复 FP | 93.28 | 90.82 | −2.45 |
| 去掉定位 FP | 93.89 | 88.85 | −5.03 |
| 去掉背景 FP | 94.81 | 89.34 | −5.47 |
| 类别 NMS .7（重新匹配） | 93.19 | 90.68 | −2.51 |
| 类别 NMS .5（重新匹配） | 93.02 | 91.37 | −1.65 |

- **重复 FP 能解释的部分：** 约 2.7 个点，即 5.15 个点中的 53%。
- **剩下约 2.45 个点：** 不能用单独去掉某一类 FP 解释。证据指向“同一个 GT 的 TP 落到了低分位置”。
  - 1.4 中 E1 在 s≥.5 处的 TP 少了 2,259 个。
  - 任务二显示，OGSOD 上被选为 TP 的最高分 query 的中位分数从 .657 降到 .436。
  - TP 排位靠后之后，跨图像汇总的 PR 曲线在召回 .6–.9 一段被各类 FP 压低（图 3）。
- **OGSOD tank 的召回上限下降：** PR 曲线在 IoU .5 的最大召回从约 .87 降到约 .80。一个可能的解释是每图每类前 100 的截断被重复框占满，但这一点没有单独验证。
- **NMS 对照：**
  - E1 加 NMS .7 后 AP 为 65.52，AP75 为 72.28，仍然领先 E000（不加 NMS）2.0 个 AP75。
  - E1 加 NMS .5 后 AP75 降到 68.46，低于 E000（不加 NMS）的 70.26；E000 自己加 NMS .5 只掉 0.86。

  所以 E1 的 AP75 收益有相当一部分依赖“同一目标有多个互相重叠的假设框”：最高分框的 IoU < .75 时，次高分、IoU ≥ .75 的框在 .75 阈值下补位成为 TP。这一点与任务二吻合：最高分 query 的 IoU 中位数没有变化（.864 vs .866）。

另外，按“在哪些阶段被匹配”划分，BP-CB query 的模式两次运行相近：
- 约 44% 只在 encoder 被匹配（模式 `100000`），其余主要在 pre / dec1 被匹配。
- E1 在 dec3 被匹配的比例反而更低（.075 vs .100）。

结论：

1. **E1 的 BP-CB query 数量是 E000 的 4.3 倍**（每个 GT 从 0.05 个增加到 0.216 个），框质量也很高（IoU 中位 .818，70% ≥ .75），但大多数分数很低（中位 .121）。它们是匹配 query 的“近似副本”。
2. **BP-CB 不是高分重复 FP 的主要来源。** 在 s≥.3 的重复 FP 中，BP-CB 只占 6%（OGSOD tank 9%）。按同一口径估算 E1 全部 5,989 个高分重复：
   - 约 25% 是末层匹配 query 本身：它输给了另一个分数更高的 query，于是自己被算成重复；
   - 约 6% 是 BP-CB；
   - 约 69% 是在这一检查点上**任何阶段都不是正样本**的 query。

   OGSOD tank 的对应比例约为 21% / 9% / 70%。上一轮报告推测“BP-CB 被反复当作正样本，因而拿到中等分数”，在单一检查点上这个推测不成立：大多数高分重复 query 当前根本不在任何正样本集合里。
3. **OGSOD tank 是例外，BP-CB 已经与匹配 query 不分高下：** BP-CB 的分数中位数 .307，与匹配 query 的 .317 几乎相同，56% 的 BP-CB 分数高于匹配 query。但框比匹配 query 好的只有 4%。分类分数没有区分“被选中的”和“没被选中的”。
4. **20 个案例**（每例左右并排：左 E000、右 E1；黄框 = GT，绿框 = 末层匹配，红框 = BP-CB，蓝框 = 其他 s≥.3 且 IoU≥.5 的候选）：
   - OGSOD 6 例、other_512 4 例、other_256 3 例、MSAR 3 例，其余来源 4 例。
   - 典型形态：E000 中同一 GT 只有一个绿框；E1 中绿框和红框（或蓝框）几乎重合，分数都在 .4–.6，IoU 都在 .8 以上。例如 case 03：E1 的匹配框 s=.59、IoU .86，BP-CB s=.48、IoU .87。

## AP50 下降原因的证据链

1. **AP50 的损失是显著的**（−5.2，CI [−5.87, −4.50]），主要集中在 OGSOD（tank、bridge）和 other_1000 ship。other_512 aircraft 的下降几乎全部由重复框解释。
2. **约一半来自重复 FP：** 去掉重复 FP 的 oracle 补回 2.7 个点；NMS .7 补回 2.5 个点。重复 FP 在 s≥.3 时增加 16 倍，s≥.05 时增加 51 倍。
3. **另一半来自 TP 排位下降：** s≥.5 的 TP 少了 2,259 个；OGSOD 最高分框的中位分数从 .657 降到 .436。TP 与 FP 在分数上的分离度变差。
4. **两部分的共同根源**（任务二）：同一 GT 周围有多个质量相近的 query，分数被分摊。≥2 个高分候选的 GT 从 1.6% 升到 18.2%。最高分 query 与 matcher 选择的一致率从 .974 降到 .784（OGSOD tank 降到 .319）。
5. **高分重复主要不是 BP-CB**（任务三，只占 6%），而是在这一检查点上不在任何正样本集合里的 query（约 69%）。
   - 因此在训练末期，这些 query 在 MAL 中是负样本，却仍然拿到中等分数。
   - **推测，尚未验证：** 分类代价降低后，正样本身份主要由几百分之一级别的框差异决定，这种差异无法从特征中预测。分类头因此学不会“只给一个 query 高分”。支持这一推测的已有证据：
     - E1 报告中，4 层匹配到同一 query 的比例从 .836 降到 .761；
     - EMA 重放显示，这一差距主要在第 20 轮之后拉开；
     - 本次测得的最高分 = 匹配 query 比例下降。
   - 但这一推测需要直接测量训练中正样本身份的稳定性，单一检查点不能证明它。
6. **AP75 的收益要打折理解：** 最高分框的 IoU 没有提高。一部分收益来自“IoU < .75 的最高分框被 IoU ≥ .75 的次高分框补位”。E1 加 NMS .5 后 AP75 低于 E000。

## 下一组实验建议（每条都标明证据依据；不提出新模块）

按代价从低到高排列：

1. **[无训练] 正样本身份稳定性测量**，直接检验第 5 点的推测。
   - **做法：** 对同一批 val 图施加训练时用到的扰动（水平翻转、光度变化，以及固定种子的多次 EMA 前向），统计每个 GT 的末层匹配 query 是否保持不变，以及最高分 query 是否保持不变。E000 与 E1 对照。
   - **依据：** 第 4、5 点；E1 报告中的 same_dec_all 和 EMA 重放的时间点。
   - **判定：** 若 E1 的匹配身份稳定性明显低于 E000、而最高分身份同样稳定，就说明“分类头无法预测 matcher 的选择”成立，后续方向应聚焦于让正样本身份稳定，而不是改变它选谁。若两者没有差别，就否定这一推测。
2. **[一次训练] 分类代价剂量-响应：cost_class = 1.0。**
   - 已有配置 `deim_hgnetv2_m_sardet100k_match_cls1_36e_b32.yml`，之前的那次运行中途停止。
   - **依据：** 目前只有 2 和 0.5 两个点，无法区分“单调权衡”与“0.5 越过了阈值”。1.4 和任务二的指标为这次运行提供了现成的判读口径。
   - **预先登记的判定：** 重复 FP（s≥.3）、≥2 个高分候选比例、最高分 = 匹配 query 比例这三个指标若随 cost_class 单调变化，且 AP75 收益与 AP50 损失同步缩小，就确认这是一个代价权衡，单靠调整系数无法同时得到两者。若 cost_class 1 时 AP75 仍有大部分收益、而重复基本不出现，就说明存在可用的折中点。
3. **[已排队] E007（不用 MAL，改用 VFL，去掉 Dense O2O）。**
   - **依据：** 任务三表明，高分重复主要来自 MAL 负样本，却仍然拿到中等分数；E007 能回答这一现象是否与 MAL 的 p^1.5 负样本权重有关。
   - **建议：** 对 E007 跑同一套 e1_followup 分析，可以直接与本表对照。
4. **暂不推进的方向：** 不推进“同一 GT 的多个候选按 IoU 排序”一类同时给多个 query 正向分类目标的做法。
   - **依据：** E1 已经表明，只要同一 GT 附近有多个 query 被推高分数，重复抑制就会崩溃（任务二第 3 点）。
   - **前提：** 任何排序类方案都必须保证每个 GT 只有一个高分 query。是否值得做，取决于第 1 条测量的结果。
5. **评测口径提醒：** 1.5 中的 NMS 结果只是诊断。DEIM 的评测协议不加 NMS，论文结果不能使用 NMS 后的数字。
