## 1. D-FINE 当 baseline 是否可行

**结论：可行，但要满足一个前提——1024 协议下的 baseline 必须进入文献的同一档（test AP50 ≥ 约 83）。**

支持的理由：

| 依据 | 说明 |
|---|---|
| 同族 DETR 在该数据集上能到 85–88 | SAR-Net 文中 RT-DETR 87.6（800 输入、300 轮）；PGD 文中 DINO-R50 85.2（1024、300 轮）。D-FINE 是 RT-DETR 的直接后继 |
| 对标论文的空白正好在这里 | PGD 只在 YOLOv5/8/10 上验证，SEFFNet 只用 YOLOv5s；没有 DETR 类的物理引导方法 |
| 基线本身够新 | D-FINE（ICLR 2025）、DEIM（CVPR 2025），实时 DETR 的代表 |
| 工程现成 | 本仓库的 DEIM-D-FINE-M、1024 配置、test 评估脚本、诊断工具都已就绪；仓库里也有 plain D-FINE-M、RT-DETRv2 配置可作对照 |

要先解决的问题：

- **差距 20 个点。** 我们 640 下 test AP50 为 65–67，而 PGD 表中 YOLOv8-R50 为 88.7，官方论文 Faster R-CNN 为 76.1。
  第 2 节的分析认为主要原因是输入尺寸（640 下 1500 图中的飞机只剩约 37 像素）和训练长度，
  但这只是推断，要等 1024 结果验证。
- **命名。** 本仓库的 baseline 是 **DEIM-D-FINE-M**（D-FINE 模型 + DEIM 的 Dense O2O 与 MAL 训练）。论文里应如实写成
  "DEIM-D-FINE-M"，并另跑一组 plain D-FINE-M 作对照，说明 DEIM 训练本身贡献了多少。
- **模型规模。** D-FINE-M 约 19M 参数，PGD-YOLOv8（R50）约 50M。主表以 M 为主；若最终方法有效，补一组 L 规模（约 31M），
  展示同等规模下的比较。

**判定规则（1024、102 轮 baseline 跑完后）：**

| 1024 baseline test AP50 | 判断 | 下一步 |
|---|---|---|
| ≥ 83 | 进入文献档位 | 按本方案推进 |
| 75–83 | 差距主要在训练长度或增强 | 先完成第 3 节阶段 2、3（增强、轮数），再判断 |
| < 75 | 不只是分辨率问题 | 先做校准：用 PGD 官方 YOLOv5 代码在同一 test.json、同一 COCO 评估下跑一次，查清是评估口径、检测器还是训练设置的问题，再决定是否换 baseline |

## 2. 改进方法：散射物理先验引导的实时 DETR

主线：PGD 的物理先验依赖外部预训练网络（PGSSL），且只适用于密集检测器；SEFFNet 的结构张量先验只在输入端做硬掩码。
我们把**解析计算、无需外部数据**的散射先验接进 DETR 的三个关键环节——encoder 特征、query 选择、decoder 采样，
并让它们尽量只在训练期起作用，推理开销接近零。

诊断给出的针对性：型号错误集中在**没见过的飞机**上（test 无匹配子集型号正确率 0.41，见过的 0.94），
所以方法应该提供与具体实例无关的结构线索，而不是增强记忆；REM 的增益来自见过的目标，正说明了这一点。

### M0 散射先验图（数据侧，不是网络模块）

- 在幅度图上用结构张量 / Harris 响应计算散射响应 R（SEFFNet 的 SIEEM 同源），GPU 上用固定卷积实现，推理时也能算，开销可忽略。
- 训练标签：每个 GT 框内保留 R ≥ η × 框内最大值的强散射点（PGD 的 PGIP 规则），得到二值散射点图 S；框外为 0。
- 离线检查：随机抽样可视化，确认 S 落在机身、发动机、翼根与尾翼上；η 取 2–3 个值作敏感性分析（补 PGD 的缺口）。

### M1 散射感知的 encoder 辅助监督（SAS，复现 PGD-PGIP 的 DETR 版）

- 在 HybridEncoder 的 stride-8 与 stride-16 输出上接轻量头（1×1 + 3×3 + 1×1），预测 S，用 focal loss 监督。
- 只在训练期计算，推理时去掉，**零推理开销**。
- 它也是"PGD 迁移到 D-FINE"的对照行；单独有效与否都可以写：有效说明物理先验能迁移，无效说明需要 M2、M3 这类 DETR 专用设计。

### M2 散射引导的 query 选择（SQS，本文核心之一）

- D-FINE 按 encoder token 的分类分数取 top-k 作为初始 query。改为：选择分数 = 分类分数 × 散射得分^α，散射得分来自 M1 的头。
  α 可学习或固定。
- 推理开销是 M1 的轻量头，约增加 <1% FLOPs。
- 可直接量化：top-k query 覆盖 GT 的召回率、落在杂波上的 query 比例。这些是 PGD 在 YOLO 上做不了的分析。

### M3 散射点引导的可变形采样（SPS，本文核心之二，针对型号区分）

- D-FINE decoder 的可变形注意力采样点是自由学习的。对匹配上 GT 的 query，加一个训练期损失：
  按注意力权重加权，惩罚采样点到最近强散射点（S 中的点）的距离（Chamfer 式）。
- 让 decoder 去看发动机、尾翼这些区分型号的强散射部位，**零推理开销**。
- 若损失版增益不足，再试显式版：在预测框内取 top-K 散射点的特征，经一层小型 self-attention 后加到分类分支（有少量推理开销）。

### 不纳入主线的已有模块

REM（640 / 102 轮 test +1.57 AP）在新协议下作为特征侧候选重新跑一次；但诊断显示它的增益来自见过的目标，不作为核心贡献。
CLCR-Lite、W-FDR、PACFG 等不再跟进。

## 3. 训练协议（先定好，定完冻结）

### 3.1 现在就固定的项

| 项目 | 设置 | 依据 |
|---|---|---|
| 数据与划分 | 官方 SAR-AIRcraft-1.0，train 3047 训练，val 442 选权重，test 879 报告；不改划分、不去重 | 与 PGD 完全相同；用户已定官方划分不变 |
| 最终表 | 另给一组 train + val（3489）固定日程、取最后一轮的结果（方案 B） | 与官方识别实验、SAR-Net 可比；做法见协议 v2 §1 |
| 模型与初始化 | DEIM-D-FINE-M，COCO M 权重 `-t` | 现有基座 |
| 输入 | 训练 1024，多尺度 768–1280；测试 1024 单尺度，无 TTA | PGD 1024 |
| 优化器 | AdamW，lr 2.3e-4，骨干 2.3e-5，WD 1e-4，全局 batch 12，warmup 约 18 轮 | v2 阶段 1，已按 batch 缩放 |
| EMA / AMP | EMA 0.9999；FP16 + FP32 loss / retry | 现有 |
| 指标 | 主：test AP50（COCO 101 点，索引 1）；辅：AP@[.5:.95]、AP75、逐类 AP50、参数量、GFLOPs@1024、FPS（4090，batch 1，FP16） | 与官方、PGD 同口径；补上二者缺的指标 |
| 种子 | baseline 与最终方法 3 个种子（0/1/2），报均值 ± 标准差；消融单种子，差异 <1 AP 标为不确定 | test 有效样本约 381 架不同飞机 |
| 消融日程 | 消融与主表用**同一日程** | 避免 PGD 消融 50 轮、主表 300 轮对不上的问题 |
| 诊断 | 每个模块都给 test 见过 / 没见过子集的对比（内部诊断，不改官方指标） | 判断增益是泛化还是记忆 |

### 3.2 需要实验确定的 trick（单因素、依次进行，定完冻结后再做模块）

| 阶段 | 变量 | 候选 | 证据 | 状态 |
|---|---|---|---|---|
| 1 | 输入尺寸 | 640 → 1024 | PGD 1024、SAR-Net 800；散射点尺度分析 | **在跑** |
| 2a | 光度增强 | 去掉 `RandomPhotometricDistort` | SAR-Net 认为 HSV 对 SAR 无益；SAR 幅度的统计分布与光学不同 | 待做 |
| 2b | 水平翻转 | 去掉 `RandomHorizontalFlip` | SAR-Net 认为无益；翻转改变阴影与叠掩方向 | 待做 |
| 2c | 斑点重采样（可选） | 保留确定分量、乘以新 Gamma 斑点（ENL≈4.6） | 重复切片中同一飞机斑点完全相同；针对见过 / 没见过差距 | 待做，有效则作为 trick 写进协议，所有方法共用 |
| 3 | 训练轮数 | 102 → 150 / 200 | 文献普遍 300 轮；看 1024 下 val 曲线在 102 轮时是否仍在上升 | 待做 |

保持不变：Mosaic（输出为输入的一半）、mixup 区间、关闭 ZoomOut / IoUCrop、DEIM 的 flat + no-aug 阶段结构。

采用规则：val 与 test 同向，且 test AP50 增益 ≥ 1（单种子噪声约 1 AP）才采用。
这些都是对 baseline 和所有方法统一生效的全局设置，在论文中如实说明 trick 的选择过程。
val 与 train 重叠 82%，单看 val 偏向记忆，所以不只看 val。

日程：阶段 2 每组一次 1024 / 102 轮运行；阶段 3 只在阶段 2 定型后跑一组更长的日程。阶段 3 定下的轮数就是之后所有消融与主表的日程。
若 150–200 轮的单次耗时无法承受，消融可以退回 102 轮，但主表要在同一 102 轮下另报一组，保证两者对得上。

## 4. 时间线

1. 等 1024 baseline（阶段 1）结果 → 按第 1 节判定规则决定是否推进。
2. 与阶段 2、3 并行（不占 GPU）：写 M0 散射图生成与可视化检查、M1 辅助头；本地只做功能正确性检查。
3. 协议冻结后：baseline 3 种子；M1 → M2 → M3 依次上服务器。
4. 对照模型与 PGD 官方代码校准，可以穿插在空闲 GPU 上跑。
