# D6 跨目标的 Query 身份追踪 与 D7 分类分数和定位质量的直接关系

这一轮不训练、不改结构，只用服务器 CPU（GPU 4、5 正在跑 E008）。E1 = E004（matcher 分类代价 0.5）。

## 口径

- **方法：** 离线重放，与 D5 完全一致，D5 的 OGSOD tank 数字在这里原样复现（第 35 轮 E000 .899 / .042，E1 .319 / 1.574）。
  - 两个运行各用自己的 EMA 检查点：第 3、7、11、15、19、23、27、31 轮，以及第 35 轮（`best_stg2`）。
  - 输入固定为 val 图，不加增强；每个运行用自己的 matcher；union set 用 `_get_go_indices`。
  - 它反映的是模型在这些轮次的匹配状态，不是训练 batch 上的分配记录。
- **单元格：** 6 个，共 3,199 张 val 图。

| 单元格 | GT 数 | 作用 |
|---|---:|---|
| ogsod/tank | 1,216 | 已有（D5） |
| ogsod/bridge | 3,224 | 是否跨类别复现 |
| ogsod/harbor | 404 | 小样本类别是否复现 |
| other_1000/ship | 127 | 是否跨来源复现（样本少，置信度低） |
| msar/tank | 522 | 对照 |
| msar/ship | 2,017 | 补充对照：同为 ship、但来自另一个来源 |

- **候选：** 在每个阶段（enc、pre、dec1–4）分别取。同类 GT 中以该 GT 为最大 IoU 对象、且 IoU ≥ .1 的 query 都是它的候选；分数是该类 logit 的 sigmoid。
  - m = 该阶段 matcher 给这个 GT 选的 query；top = 分数最高的候选；best = IoU 最高的候选。
  - ΔS = S(m) − S(top)，ΔIoU = IoU(m) − IoU(top)。
- **未匹配高分 query：** 分数 ≥ .3、IoU ≥ .5，并且这次前向在任何阶段都没被匹配给任何 GT 的候选。
- **竞争对（D7）：** 同一 GT 的两个候选，IoU 都 ≥ .5，且至少一个分数 ≥ .1。
  - 排序正确率 = IoU 更高的那个分数也更高的比例。0.5 表示等同于随机猜。
  - 按两者在该层 decoder 特征上的余弦相似度分档。
  - 不加分数门槛的“全部对”主要由分数接近 0 的尾部组成，没有判读价值，只放在 JSON 里。
- **代码：** `tools/sardet100k/cell_identity_epochs.py`。
- **输出位置：**
  - 服务器：`independent_verify_20261106/` 下的 `d6_cells_E000`、`d6_cells_E004`（全部轮次），以及 `d7_pairs_E000`、`d7_pairs_E004`（第 35 轮，含竞争对和 matcher–top 余弦）。
  - 本地：`analysis_outputs/d6_d7/`。

### 对四个问题的回答

1. **OGSOD bridge 也出现脱离，而且起点比 tank 更低。**
   - 第 3 轮 E1 只有 13% 的 GT，其最高分 query 是 matcher 选的那个（E000 为 79%）。到第 35 轮只回升到 45%（E000 为 97%）。
2. **未匹配高分 query 随训练持续增加的，只有 OGSOD tank 和 OGSOD bridge。**
   - tank 从第 3 轮起单调增加，到 1.57 个 / GT。
   - bridge 在第 19 轮之前平稳（约 .1），之后快速增加到 .60 个 / GT。
   - harbor、other_1000 ship、MSAR ship 在训练前期较高，后期回落。
3. **MSAR 基本保持正常收敛。**
   - MSAR tank 在两个运行中都正常。
   - E1 的 MSAR ship 前期也脱离（第 3 轮 .58），但训练中恢复到 .93；未匹配高分 query 从 .27 降到 .07。它最终正常，只是仍略差于 E000（.998 / .002）。
4. **other_1000 ship 也存在：** 第 35 轮最高分 = matcher 只有 .575（E000 为 .898），未匹配高分 query 在 .3–.7 之间波动，没有单调趋势。它只有 127 个 GT，结论置信度低。

### 判读

E1 的脱离在所有单元格的训练初期都出现，连 MSAR ship 也是如此（MSAR tank 很轻，.927）。因此脱离本身是降低分类代价带来的共性现象，并不专属于 tank 或 OGSOD。各单元格的区别在于训练能不能把它纠正回来：
- **能纠正：** MSAR tank、MSAR ship、OGSOD harbor。
- **纠正不了：** OGSOD tank 一直不变，OGSOD bridge 部分回升，other_1000 ship 部分回升；未匹配高分 query 在 OGSOD tank、OGSOD bridge 上持续累积。

所以它既不是“只有 tank”（OGSOD bridge 也有），也不是“只有 OGSOD”（OGSOD harbor 能恢复，other_1000 ship 也有问题）。什么情况下能恢复，要看 D7。

## D7：分类分数能否反映定位质量

### 脱离最早发生在哪一层

最高分 = matcher 的比例在 enc → pre → dec1 → dec4 之间基本不变。以第 35 轮 E1 的 OGSOD tank 为例：.345 / .281 / .286 / .311 / .320 / .319。bridge 和其他单元格也是同样的形态，见服务器上 `d6_cells_*` 的 JSON 中 `stages` 字段。

**结论：** 脱离在 encoder Top-K 阶段就已经确定，6 个阶段的 matcher 各自独立匹配，得到的不一致程度相同；不是哪一层 decoder 引入的。

- **E1 的 OGSOD：** 这类候选每个 GT 有 2.0 个（tank）和 0.69 个（bridge），框质量高（IoU 中位 .62–.66）。它们和正样本一样好，只是没有被 matcher 选中。
- **为什么负样本还能拿到高分：** 见下一节。它们的特征和正样本几乎一样，分类头没有依据把它们压下去。

### 分类分数能不能区分“外观相近、定位不同”的两个 query

**竞争对排序正确率（末层，第 35 轮，IoU 差 ≥ .1）**

| 单元格 | E000：余弦 < .9 | E1：余弦 < .9 | 竞争对中余弦 ≥ .9 的比例（E000 / E1） | 余弦 ≥ .98 档的排序正确率（E000 / E1） |
|---|---:|---:|---|---|
| msar/tank | **1.000** | .998 | .000 / .003 | 两边都几乎没有这种对 |
| msar/ship | .986 | .833 | .003 / .420 | .44（9 对）/ .59 |
| ogsod/harbor | .948 | .775 | .015 / .496 | .57（7 对）/ .65 |
| ogsod/bridge | .878 | .648 | .025 / .545 | .52 / .57 |
| other_1000/ship | .800 | .414 | .128 / .694 | .33（18 对）/ .58 |
| ogsod/tank | **.678** | .629 | .086 / .646 | .62 / .54 |

另外，在最高分 query ≠ matcher 的 GT 上，两个 query 的末层特征余弦中位数：E000 OGSOD tank 为 .988，E1 为 .990（69% 的 GT ≥ .98）；E1 OGSOD bridge 为 .978。在 dec1，同一对的余弦中位数只有 .82 和 .67。也就是说，两个竞争 query 的特征是在 decoder 中逐层趋同的，而它们的框仍然相差 0.16–0.18 IoU。

**读法：**

1. **特征几乎相同的两个 query，任何运行都无法按定位质量排序。** 在余弦 ≥ .98 一档，所有单元格的排序正确率都在 .5–.6 左右，接近随机。分类分数由 query 特征计算（LQE 再加一个由框分布得出的小修正，量级约为 logit 的 1/20，见 tank 诊断），特征一样，分数就分不开。
2. **E000 基本不出现这种情况，E1 大量出现。** E000 的竞争对中，特征近乎相同的只占 0–13%；E1 中占 42–69%。E1 让多个 query 收敛成同一目标的近似副本，这是分类无法区分它们的直接原因。
3. **即使在特征不同（余弦 < .9）的竞争对上，OGSOD tank 的排序能力也明显偏弱，而且 E000 本身就弱。**
   - E000 中 MSAR tank 为 1.000、MSAR ship .986、OGSOD harbor .948，而 OGSOD bridge .878、other_1000 ship .800、OGSOD tank 只有 .678。
   - 也就是说，在 OGSOD tank 上，两个 IoU 差 0.1 以上、特征也不同的框，基线模型也只有约 2/3 的概率把更好的那个排在前面。
4. **基线的排序能力与 E1 能否恢复对得上。** E000 竞争对排序正确率最高的三个单元格（MSAR tank、MSAR ship、OGSOD harbor）正是 E1 在训练中恢复的三个；最低的三个（OGSOD bridge、other_1000 ship、OGSOD tank）正是 E1 恢复不了、或只部分恢复的三个。
   - 这只是 6 个单元格上的对应关系，不是因果证明。
   - 解释是：matcher 偏向选更准的框时，分类头只有在本来就能按定位质量排序的数据上才跟得上。

## 结论：值得改进的网络能力

D6 和 D7 指向同一件事：在 OGSOD tank（其次是 OGSOD bridge、other_1000 ship）上，分类分数不能区分同一目标附近定位质量不同的 query。原因有两层：

1. **基线就存在的能力缺口：** 即使特征不同，OGSOD tank 竞争对的排序正确率也只有 .68（MSAR tank 为 1.0）。分类分支拿不到足够的定位质量信息。
2. **E1 放大了它：** 竞争 query 的末层特征趋同（余弦 ≥ .98），分类在原理上无法区分；而它们的框仍有约 .17 IoU 的差距，说明框分支保留了分类分支看不到的差异。

这比 D5 的结论更具体：问题不在 matcher 选谁，而在分类分支缺少一个能看到“这个框有多准”的输入。当前 LQE 只使用末层边分布的 top-4 统计，量级约为 logit 的 1/20，在 OGSOD tank 上无效（见 tank 诊断第 8–14 节）。

### 下一步建议（依据都来自本轮数据，不是新模块方案）

1. **[CPU，可立即做] 定位信息在分类分支中可用吗？** 在 E000 第 35 轮，用 OGSOD tank 竞争对，比较三种排序信号的排序正确率：分类 logit、LQE 输入的边分布统计、框分支的中间特征。若后两者明显好于 logit，就说明信息已经在网络里，只是没有传到分数上；若同样接近随机，就说明需要新的定位证据（例如来自图像的局部结构）。这一项直接决定方法方向。
2. **[CPU] 把 D7 的竞争对分析扩展到 E000 的全部来源 × 类别。** 确认“排序正确率低”的单元格与“AP75 低 / swap oracle 增益大”的单元格是否一致，从而把能力缺口与论文指标挂钩。
3. **训练层面的处理放到第 1 条之后。** 分数与定位的耦合依赖分类分支能拿到什么输入，在不知道信息是否已经存在之前，调损失或 matcher 都是盲调；E1 已经表明，单改 matcher 会放大问题。

### 局限
- other_1000 ship 只有 127 个 GT，竞争对的分档样本少；E000 余弦 ≥ .9 的各档有些只有个位数到几十对，这些格子的数值只作参考。
- 余弦是在每层 decoder 输出特征上算的；末层特征整体就很相似（全部对的余弦中位数为 .94–.99），所以 .9 / .98 是相对门槛，只能在同一层、同一单元格内比较两个运行。
- 本轮没有计算图像级 bootstrap 区间。
- 训练 batch 上的逐步身份记录仍未做，需要 GPU 和训练（同 D5）。
