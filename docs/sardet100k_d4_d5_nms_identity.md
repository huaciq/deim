## D4：类别内 NMS 阈值扫描

### 口径
- **输入：** 两个运行各用自己第 35 轮的 EMA 权重，末层 300 个 query 的输出直接复用 e1_followup 已收集的 `queries.npz`。
- **检测框：** 按原后处理规则生成（sigmoid，在 300×6 上取前 300）。
- **NMS：** 在这 300 个检测框上做类别内贪心 NMS，框和分数都不改。
- **评测：** 不变（COCO 规则：每图每类前 100，101 个召回点）。
- **比较方式：** E000 和 E1 用同一个阈值比较。配对 bootstrap 以图像为单位重采样 200 次，两个运行用同一组样本。
- **复现检查：** 不加 NMS 一行复现了日志：E000 AP50 / AP75 为 93.145 / 70.262，E1 为 87.996 / 73.203。

### D4 结论

1. **E000 不需要 NMS：** 任何阈值都不比不加 NMS 更好（AP 最高 65.29，即不加时）。E1 在 0.75 时最好，AP 65.90。
2. **同阈值下的公平对照：** 0.70–0.80 区间内 E1 的 AP 显著高于 E000，约 +0.6 到 +0.7，CI 不含 0。以 0.75 为例，ΔAP CI 为 [+0.33, +1.04]。
   - 这个优势完全来自高阈值：ΔAP75 为 +2.8 到 +4.1，AP50 仍然低 2.5–3.5。
   - 之前“E1 + NMS 0.7 = 65.52 对比 E000 不加 NMS”的比较作废。按同阈值比较，0.70 时为 65.76 对 65.14。
3. **没有一个阈值能“保留 AP75 收益、同时基本恢复 AP50”：**
   - 阈值越低，AP50 恢复得越多，但 AP75 收益同时消失。0.60 时 ΔAP50 −1.2、ΔAP75 +0.5（CI 含 0）；0.50 时 AP75 反而低 0.8。
   - 在 OGSOD tank 上这个此消彼长最明显：0.50 时 AP50 恢复到 71.1，AP75 却降到 13.9；0.80 时 AP75 为 20.1，AP50 只有 57.7。
4. **AP50 有一部分是 NMS 补不回来的：**
   - 即使在 0.50、重复 FP 几乎清空（s≥.3 时只剩 62 个）的情况下，E1 的 AP50 仍低 1.0（CI [−1.50, −0.64]）。
   - s≥.5 的 TP 在所有阈值下都约少 2,260 个，TP 分数的 10% 分位是 .36，E000 是 .58。也就是说，E1 有一批 TP 的分数本身就低，这和重复框是两件事。
5. **E1 的 AP75 收益确实靠重叠的多个假设框：** 阈值从 0.80 降到 0.50，E1 的 TP@.75 从 20,288 个降到 17,399 个，而 E000 只从 18,301 个降到 17,478 个。
6. **工程层面：** E1 + NMS 0.75 的 AP 比 E000 高 0.6，代价是 AP50 低 3。在 AP50 更受关注的场景下，这个交换不划算。DEIM 的标准协议不加 NMS，所以这一结果不进入论文结果，也不作为创新点。

## D5：训练过程中的 Query 身份

### 实际拥有的检查点
- 两个运行都只保留了第 3、7、11、15、19、23、27、31 轮的 `checkpointNNNN.pth`，以及第 35 轮的 `best_stg2.pth`。
- 没有第 5、10、20、25、30 轮，因此用相邻的轮次代替。
- 这些检查点都带有 EMA 权重。

### 口径
- **方法：** 离线重放。每个检查点的 EMA 权重处理同一批固定的 val tank 图：OGSOD 1,216 个 tank GT，MSAR 522 个作为对照；输入与评测一致，不加增强。
- **匹配：** 每个阶段（encoder Top-K、pre、dec1–4）都用该运行自己的 matcher 匹配。union set 用 `_get_go_indices`，与训练一致。
- **Query ID 的比较范围：** 只在同一次前向的各阶段之间比较，不跨检查点比较。encoder 的 Top-K 会随权重改变，不同检查点的同一个 ID 不是同一个 query。
- **复现检查：** E1 第 3 轮 4 层同一 query 的比例为 .808，与先前重放的 .8084 一致；第 35 轮 E000 为 .836、E1 为 .756，与 E1 对照报告的 .836 / .761 基本一致（后者由单独一次收集算出）。
- **定义：**
  - 候选：在 dec4 的 tank GT 中，以该 GT 为最大 IoU 对象、且 IoU ≥ .1 的 query。
  - 未匹配高分 query：分数 ≥ .3、IoU ≥ .5，并且在这次前向的任何阶段都没有被匹配给任何 GT 的候选。

### D5 结论

1. **E1 确实越来越多地出现高分、但没被匹配的 query，不过这一趋势不是从第 20 轮才开始：**
   - E1 的未匹配高分 query 从第 3 轮起单调增加：每个 GT 从 .107 增加到 .285（第 7 轮）、.621（第 15 轮）、.881（第 19 轮）、1.246（第 23 轮），到第 35 轮为 1.574。
   - E000 在第 15 轮达到峰值（.173）后回落到 .042。
   - 两条曲线从第 7 轮起就分开了；第 15 轮以后，E000 开始自我纠正，E1 继续累积。所以“第 20 轮后拉开”更准确的说法是：E000 在中后期把这类竞争收敛掉了，E1 没有。
2. **核心区别不是层间身份不稳定，而是分类分数始终没有对齐 matcher 的选择：**
   - 4 层同一 query 的比例两者只差 0–8 个百分点，前 23 轮的差距在 4 个点以内。
   - “最高分 = 末层匹配”的比例：E000 从 .486 一路升到 .899；E1 在全程 36 轮里一直停在 .27–.35，没有上升。
3. **E1 的 matcher 从一开始就选中了最佳框（.93–.96），但分类头没有学会给这个 query 最高分：**
   - 到第 35 轮，E1 的匹配 query 框更好（IoU .799 对比最高分 query 的 .663），分数却更低（.327 对比 .401）。
   - 这个关系在 encoder 阶段就已经存在，并沿各层保持下去（见轨迹表），不是 decoder 某一层引入的。
   - E000 则相反：matcher 越来越多地选中最高分的那个 query，最佳框并不总被选中，即末层匹配 = 最佳框的比例从 .79 降到 .48。
4. **对先前推测的修正：**
   - e1_followup 报告提出“正样本身份在相邻 query 间轮换，导致分数被分摊”。D5 不支持其中“层间轮换”这一部分。
   - 更符合数据的描述是：降低分类代价后，matcher 选择的 query 与分类头打分最高的 query 从训练初期就不一致，而且这种不一致在 36 轮内没有被纠正。被 MAL 当作负样本的高分 query 越积越多，分类头一直在追 matcher 的选择，却始终没追上。
   - 至于在训练 batch 上，正样本身份是否跨训练步来回切换，单个检查点的重放回答不了，需要逐 batch 记录正样本身份（见下文“未做”）。

## 本轮未做的（需要 GPU 或训练）

1. **训练时逐 batch 记录正样本的 query ID 和跨步变化：** 需要在 `DEIMCriterion` 里加轻量日志，并重新训练 E000 和 E1。现有的 `log_matching_stats` 只记录批内汇总，不记录 query ID 和跨步的身份变化。这一项需要 GPU 和训练，本轮没做。
2. **第 5、10、20、25、30 轮的重放：** 这些轮次没有保存检查点，用第 3、7、11、15、19、23、27、31 轮代替。若需要精确轮次，只能重训并改变保存间隔。
3. **E000 的训练时匹配统计：** E000 训练时没有开 `log_matching_stats`，没有记录。
4. **D5 的 bootstrap 区间：** 每个点有 1,216 个 GT，但 GT 之间按图像相关，本轮没有为 D5 计算图像级 bootstrap。
