# D7.2 联合探针 与 D7.3 质量信号的 swap oracle

接 [D7.1](sardet100k_d71_quality_signal_probe.md)。不训练、不改结构，只用 CPU。权重为 E000 第 35 轮 EMA（`best_stg2`），末层 decoder，val。

两个问题：

1. **D7.2：** box head 的特征（S4）在框几何（S0）之外，是否还带有定位质量信息？在分类分数已经用到的信息之外呢？
2. **D7.3：** 把这部分信息交给排序，能换来多少 AP？

## D7.2 联合探针

### 口径

- 与 D7.1 完全相同：同一份特征（`analysis_outputs/d71/E000.pt`）、同一批竞争对、同样的图像分组 5 折、L2 内层搜索、GT 加权和图像级 bootstrap（1,000 次）。S0、S1、S4 h1、S5 单独的数值与 D7.1 逐位一致。
- **联合信号：** 把各部分特征拼接后训练同一种线性两两排序器。
- **S0q：** 更严格的几何对照，在 S0 之外加上（cx、cy、log w、log h）的全部二次项，共 16 维。
- **差值的区间：** 两个信号在同一批竞争对上的排序正确率之差，按图像做配对 bootstrap。D7.1 只比较了两个各自的区间是否重叠，这里直接给差值的区间。
- 代码：`tools/sardet100k/quality_signal_probe.py joint`。输出：`analysis_outputs/d72/probe_joint.json`（两个 tank 单元格）、`probe_joint_bridge.json`。

### 判读

1. **OGSOD tank 上，box head 确实带有几何之外的质量信息，但量不大。**
   - 对线性几何是 +.064，对含二次项的几何是 +.040，两个区间都不含 0。
   - 加上几何后 S4 不再提高（.647 对 .646），说明 S4 已经包含了几何那部分。
   - 按交接时写定的读法，这属于“小幅超过 S0：存在额外信息，但贡献有限”。剔除几何后只剩 .04–.06，绝对水平 .647，离 MSAR 的 .95 仍然很远。
2. **“分数没有用到的信息”只在 OGSOD tank 这一个单元格出现。**
   - (S0 + S1 + S4) − (S0 + S1)：tank +.083，bridge +.002，MSAR tank −.002，后两者的区间都贴着 0。
   - bridge 上 box head 同样有几何之外的信息（+.117），但分类 logit 已经拿到了同样多（S1 .720 对 S4 .723）。
   - 也就是说，方向 A（让分数读到 box 分支已有的信息）目前的证据只覆盖 1,216 个 GT 的一个单元格，占 val 全部 GT 的 5.4%。
3. **S5 在 OGSOD tank 上超出几何的部分不显著**（+.014，区间含 0）。D7.1 中 S5 的 .595 与几何对照无法区分。E1 上“高相似度的对里 S5 仍可线性读出质量信息”的结论来自 E1 的数据，这里没有重做。
4. **探针本身有约 .02 的不稳定。** S0 + S1（.559）低于单独的 S1（.571）和 S0（.583），多加特征反而变差，只能是折外泛化的波动。所以这张表里小于约 .03 的差别不作解读。

### 局限

- 线性探针，81 张图。结论是“线性可读的下界”，非线性读出可能更多。
- S0q 只到二次项，不能排除更复杂的几何捷径。
- 排序器在每个单元格内单独训练。
- 排序正确率不是 AP。换算见 D7.3。

## D7.3 swap oracle

### 为什么不只做 OGSOD tank

晋级门槛是全 val 的 AP（[结果总表](sardet100k_results_ledger.md)：36 轮 val AP 涨 0.5 以上）。OGSOD tank 只占 tank 类 GT 的约六成，tank 又只是六类之一，单看这一格无法判断方向 A 值不值得一次训练。全 val 的交换 Oracle（[tank 诊断第 14 节](sardet100k_ogsod_tank_feature_diagnosis.md)）显示 other_512 aircraft、other_256 ship、OGSOD bridge 的排序空间都很大，而 D7.1 只探了三个单元格。所以这一轮对**全部来源 × 类别**提取特征，把结果换算成全 val AP。

### 口径

- **提取：** `quality_signal_probe.py extract --all-cells`，对 val 全部 10,492 张图各做一次 CPU 前向。同一次前向同时写出竞争候选的特征（`probe_features.pt`）和每张图 300 个 query 的 logit 与框（`queries.npz`）。
  - 不能复用 e1_followup 的 `queries.npz`：那是 GPU 前向的结果，encoder Top-300 在边界上与 CPU 前向不同，query 序号只有约一半对得上（框的差中位数 5e-5 到 6e-4，但尾部到 .01–.04；logit 差最大到 2.5）。所以本轮的基线 AP 是这次 CPU 前向自己的 AP，会与训练日志有微小出入，报告中一并给出。
- **候选集合：** 与 D7.1 相同。同类 GT 中以该 GT 为最大 IoU 对象、且 IoU ≥ .5 的 query；至少两个候选的 GT 才参与。
- **交换规则：** 在一个 GT 的候选之间重排该类的 logit，使其顺序与信号一致：信号最高的候选拿到现有 logit 中最高的那个，依此类推。
  - 分数的集合、所有的框、其他 query 和其他类别的 logit 都不变。
  - 之后按原后处理规则重建检测框（sigmoid，在 300×6 上取前 300），用 e1_followup 的 COCO 规则评测。
- **信号：**

| 信号 | 含义 |
|---|---|
| S1 final | 分类 logit 本身。用于检查：交换后应当复现基线 |
| S0 + S1 | 对照：几何加现有分数，不含 box head |
| S4 h1 | box head 第一隐层 |
| S0 + S1 + S4 h1 | 网络里现有信息的最好组合 |
| iou | 真实 IoU。这一规则下、这些候选集合内任何重排的上限 |

  向量信号用折外线性排序器的得分，训练方式与 D7.1、D7.2 相同，每个单元格单独训练；竞争对少于 50 或图少于 10 的单元格不交换。
- **输出：** 每个单元格的 AP、AP50、AP75，全 val 六类平均 AP，以及对基线的配对图像 bootstrap（200 次）。
- 这是 GT-aware 的诊断上限，不是可部署的方法：候选集合由 GT 决定，排序器用 GT 的 IoU 训练。一个真正训练出来的模块只会更低，而且还要保证不制造重复框（E1 的教训）。
- 代码：`tools/sardet100k/quality_swap_oracle.py`。服务器输出：`independent_verify_20261106/d72_probe_all_E000`（特征、`queries.npz`、全单元格的联合探针）与 `d73_swap_all_E000/swap_oracle.json`。

### 判定（先于结果写定，2026-11-10）

| 结果 | 结论 |
|---|---|
| 含 S4 的交换（S4 h1 或 S0 + S1 + S4 h1）使全 val AP 提高 ≥ 0.5，且明显高于 S0 + S1 对照 | 方向 A 值得一次训练实验，下一步写实验卡 |
| 提高 < 0.5 | 方向 A 不作为主线。它的上限已经低于晋级门槛，而上限本身还是乐观估计 |
| iou 上限也 < 0.5 | IoU ≥ .5 的候选内部重排本身没有空间；第 14 节的 +5.4 AP 来自别处（IoU < .5 的候选，或换框而不是换分数），要重新界定“排序问题” |
| S1 final 的交换不复现基线 | 工具有错，结果作废 |

另外记录每个单元格的 AP75 变化，用来判断收益是否只来自 OGSOD tank。

### 判定

按先前写定的表：

1. **含 S4 的交换没有提高全 val AP**（−0.07 与 −0.03，区间上端 +0.14 与 +0.20），远低于 +0.5。**方向 A 不作为主线。**
2. **iou 上限是 +4.74 AP、+8.59 AP75**，所以“IoU ≥ .5 的候选内部怎么排”确实有很大的空间，第 14 节 +5.4 的大部分就在这里。问题是真实的，只是现有特征解决不了它。
3. S1 final 复现基线，工具通过检查。

### 判读

1. **除 OGSOD tank 外，分类分数已经用尽了 box head 里线性可读的质量信息。** GT 数在 300 以上的其余 9 个单元格里，S4 h1 的排序正确率与分类 logit 相差都在 ±.005 以内；样本更少的几格 S4 反而略低（other_512 tank −.047）。D7.1 在 OGSOD tank 上看到的“信息在 box 分支里、分数没用上”是这一格特有的现象，不是 DEIM 分类分支的普遍缺陷。
2. **真正的缺口是信息不存在，而不是没被用上。** 上限 +4.74 AP 分布在所有来源：other_512 aircraft +7.1、OGSOD bridge +6.9、OGSOD tank +8.9、other_256 ship +4.5、car +3.3。在这些单元格里，分数最高的候选恰好是最准的那个的比例只有 .37–.65。网络在同一目标附近给出几个 IoU ≥ .5 的框，但它自己分不清哪个更准，box head 的特征里也读不出来。
3. **这不是小目标特有的。** other_512 aircraft 的目标长边多在 64–128 px，排序正确率只有 .74，上限 +14.4 AP75，是空间最大的单元格之一。所以“分辨率不够”解释不了全部。
4. **与已有结果一致：**
   - LQE 用框分布预测质量，在 OGSOD tank 上无效（D7.1）；这里说明换一个输入（box head 隐层）在其他单元格也拿不到更多。
   - E003（Q-MAL）改分类的质量目标，AP 下降；E004 改 matcher 的分类代价，AP 持平而重复框失控。两次训练都是在“分数怎么对齐定位”上做文章，都没有收益。
5. **对后续方法的含义：** 要拿到这 +4.7 AP，需要的是让网络**知道**一个框有多准的新证据，或者让同一目标附近的框本身更准、更一致，而不是在现有特征和分数之间加一条通路。

### 局限

- 探针是线性的，每个单元格单独训练。非线性读出可能更多，本轮不能排除；但 LQE 本身就是一个端到端训练的非线性读出，它在这些数据上没有做到。
- 只探了末层的 box head 第一隐层。更早的层、encoder 特征图上的局部特征没有探。
- 交换只改同一 GT 内部的顺序，不改跨 GT、跨图像的分数校准，所以它量的是“同一目标内选对框”的价值。
- iou 上限使用真实 IoU，任何方法都达不到；它只说明空间在哪里。
- 单种子、单个检查点。
