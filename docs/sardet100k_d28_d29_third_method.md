# D28–D29 与第三个方法：重新审视“已排除”的图像层面机制

日期：2026-11-13。用户认为此前排除的图像层面机制未必都没有空间，诊断可能做得不完全，要求继续分析，定下第三个方法，以便画出整体网络机制图。

本轮做了三件事：检验此前唯一没测的图像线索（目标之间的排布，D28）；检验一种 SAR 特有的小目标候选来源（散射点峰值，D29）；用正在训练的 E013-v2 回头检查此前诊断方法本身的可靠性。前两项不训练，只用 val，服务器 CPU，运行 E000（第 35 轮 `best_stg2`）。

## 一、诊断方法本身：冻结探针会漏判训练后的结构收益

D18 用冻结特征做了一个小型方向融合，结果是没有增益（裁块召回 73.1 对单视角 73.9）。按那时的读法，方向融合没有零训练支持。但 E013-v2 在同一协议下训练，每一轮都领先 E000：

| 轮 | 0 | 5 | 10 | 15 | 20 | 22 | 25 |
|---|---|---|---|---|---|---|---|
| E000 val AP | 36.39 | 47.62 | 49.49 | 52.61 | 55.53 | 57.51 | 60.33 |
| E013-v2 val AP | 36.90 | 48.96 | 51.07 | 54.25 | 57.26 | 59.61 | 62.51 |
| 差 | +0.51 | +1.34 | +1.58 | +1.64 | +1.73 | +2.10 | +2.18 |

AP50 同样每轮领先（第 25 轮 91.61 对 89.86）。最终结果要等训练结束，但领先从第 0 轮起一直没有中断。

**结论：** 冻结特征上的探针只能回答“现有特征里有没有这部分信息”，回答不了“换一种结构训练后，网络会不会学出更好的特征”。用户的怀疑是对的。据此把此前的负结果分成两类：

| 类型 | 检验 | 是否仍可靠 |
|---|---|---|
| 直接作用于检测器行为、不需要改特征的机制 | D19 同类互借尺寸、D24 解码与细化层数、D26 查询分配、D28 排布重打分、推理时 query 数、增益鲁棒性 | 可靠：这些机制本来就作用在现有输出上 |
| 冻结特征探针 | D12.3 杂波归一化、D13 上下文、D25 相位、D27 散斑统计 | **只说明现有特征已含该信息，不否定训练后的结构** |
| 训练过的结构 | E002 保护环注意力 −0.92；D20 小型像素精修器 | 只否定该实现 |

因此第三个方法的选择不再以冻结探针为否决依据，而以“检测器直接表现出来、且有量化规模的问题”为依据。

## 二、D28 目标之间的排布

工具 `tools/sardet100k/arrangement_support_probe.py`。油罐区的 tank、停车场的 car、机坪上的 aircraft、码头边的 ship 都按固定间距成排出现，杂波亮斑没有这种规律。对每个候选框，看同类高分检测（分数 ≥ .5 或 ≥ .3）中是否有两个能“预测”它的位置：延长一排（c ≈ 2a − b），或填补一排中间的空位（c ≈ (a + b)/2），容差 0.3 倍框边长。

读法（运行前写在工具里）：两半 val 交叉调参后，mAP 提高 ≥ 0.3、OGSOD tank 提高 ≥ 1.0、AP50 不降，才支持在 decoder 中加排布关系模块；mAP 提高 < 0.1 即否定。

| 位置在“排上”的比例（锚点分数 ≥ .5，括号内为 ≥ .3） | OGSOD tank | 512 car | 512 aircraft |
|---|---|---|---|
| 已检出的无副本目标 | 41.9%（68.7%） | 64.3% | 15.5% |
| 漏检的无副本目标 | 7.5%（29.9%） | 18.8% | 0% |
| 背景误检（分数 ≥ .1） | 8.2%（34.9%） | 27.9% | 6.5% |

重打分（logit 加 β，每类 β 在一半 val 上选、在另一半上测）：

| 调参 → 测试 | mAP | AP50 | OGSOD tank |
|---|---|---|---|
| 偶数图 → 奇数图 | 64.62 → 64.63 | 92.66 → 92.64 | 28.86 → 28.86（β 选为 0） |
| 奇数图 → 偶数图 | 65.73 → 65.76 | 93.73 → 93.73 | 32.79 → 32.79（β 选为 0） |

**判定：否定。** 已检出的 tank 有四成在排上，漏检的 tank 在排上的比例（7.5%）与杂波（8.2%）相同。也就是说，成排的目标检测器已经检出了；漏掉的是零散的、不在排上的目标，排布线索帮不了它们。低分段里“在排上的候选”确实更常是真目标（OGSOD tank 分数 .1–.3：28.2% 对 8.5%），但提分后 AP 不升。较可能的原因是这些候选多是已检出目标的重复框，这一点没有单独核对。

## 三、D29 散射点峰值能否为极小目标提供候选

工具 `tools/sardet100k/peak_token_coverage.py`。D26 发现 245 个 val 目标在 encoder 的 8,400 个位置上都没有能覆盖它的初始框（IoU ≥ .5），几乎都是输入长边 < 16 像素的 OGSOD tank 和 bridge。一个 SAR 特有的设想是：只在图像有强散射点（经典 CFAR 线索）的位置补 stride-4 token，而不是加稠密的 stride-4 层。在原图上取 3×3 均值的局部极大，按 CFAR 比（3×3 均值除以 15×15 窗去掉中心 5×5 后的均值）排序，每个 stride-4 格子保留一个。

读法（运行前写在工具里）：每图 256 个峰值时，命中 ≥ 90% 的极小目标、≥ 80% 的无候选目标，且峰值比对随机背景的 AUC ≥ .8，才算可行；极小目标命中 < 75% 即否定。

| 每图保留峰值数 | 64 | 256 | 1,024 | 全部（中位数 2,909 个格子） |
|---|---|---|---|---|
| 全部目标 | 76.0% | 90.4% | 98.3% | 99.8% |
| 输入长边 < 16 | 48.0% | 68.2% | 87.5% | 98.3% |
| encoder 无候选（D26 的 245 个） | 30.6% | 43.3% | 78.0% | 96.3% |
| 最终漏检且长边 < 16 | 21.1% | 31.7% | 68.7% | 94.7% |
| OGSOD tank | 27.5% | 49.5% | 88.2% | 99.0% |
| 随机背景框（长边 < 16） | 2.3% | 10.0% | 34.8% | — |

峰值比的 AUC：极小目标对随机背景 .74，对检测器的强杂波 .58。

**判定：否定。** 漏掉的极小目标不是突出的散射点，而是低对比度的小斑块；按峰值强度挑位置，恰好挑不到它们。稀疏峰值 token 不可行。

## 四、剩下的、有检测器直接证据的问题：极小目标的分辨率

把此前所有直接测在检测器上的结果放在一起，只有一个问题既规模大、又不在主线和辅助方法的作用范围内：

| 证据 | 来源 | 数字 |
|---|---|---|
| 尺寸断崖 | 基线诊断 | tank：原图长边 < 16 AP 28.7，16–32 为 87.9；bridge 25.3 对 43.3 |
| 极小目标没有候选 | D26 | 245 个目标在所有 stride 8/16/32 位置上都没有 IoU ≥ .5 的初始框；输入长边 < 16 的目标 13% 如此 |
| 定位误差随 stride-8 格内相位周期变化 | D25 | OGSOD tank 周期幅度 1.56 / 1.01 像素（x / y），打乱相位的噪声 95% 分位 0.36 / 0.40，两次运行都超出噪声 |
| 分辨率降低时极小目标先丢 | 扰动敏感性 | 降采样 0.5：长边 < 16 的已检出目标丢 28.9%，≥ 16 丢 12.3% |
| 训练时把目标缩小有害 | D12 | 去掉 Dense O2O（Mosaic 缩小目标）后，无副本 tank、bridge AP +1.9、+3.6 |
| 极小目标不是强散射点 | D29 | 需要稠密的高分辨率特征，不能只在峰值处补 |

D25 当时的判读是“分辨率不是普遍限制”，因为它要求周期部分同时超过该格子中位绝对误差的 25%。这个结论对 ship、aircraft 成立；对 OGSOD tank，周期部分在两个方向、两次运行中都超出噪声，按本节的第一条原则，冻结检测器上的这个信号不能否定训练后的 stride-4 层，反而是支持它的直接证据。

## 五、第三个方法：极小目标的 stride-4 精细层（E015）

### 结构

```
HGNetv2 ─ S2 (stride 4) ──────── 1×1 (96→128) ─┐
        └ S3–S5 → (E013-v2 方向融合) → AIFI / FPN / PAN → P3, P4, P5
                                     P3 ─ 1×1 (256→128) ─ 上采样 ×2 ─┴ 拼接 → 1×1 (256) → 2 个残差块（深度 3×3 + 1×1）→ P2
query 选择：P2 的 25,600 个 token 与 P3–P5 的 8,400 个一起按分数取前 300（P2 anchor 边长 0.025）
decoder：每层每头新增 3 个 P2 采样点（独立的 offset 和权重），原有层的形状与 COCO 权重不变
```

- **已有实现。** `engine/deim/fine_level.py`、配置 `configs/deim_dfine/deim_hgnetv2_m_sardet100k_fine_level_36e_b32.yml`（基于 E000 协议）、测试 `tests/test_fine_level.py`，设计见 [精细层设计](sardet100k_fine_level_design.md)。2026-11-06 写好后没有运行（当时的编号 E003 后来给了 Q-MAL），现在编号为 E015。2026-11-13 在当前 main 上（CPU）`python -m unittest tests.test_fine_level` 的 10 项检查全部通过：COCO 权重形状不变、配置与 E000（旧服务器配置与 E000-old）只差本模块、训练和推理前向都经过新层、激活检查点不改变输出和梯度。
- **单独实验在 E000 上做**，与 E013-v2、E010 各自对照 E000；三者组合是之后的事。组合时 E013-v2 的 S2 只取原视角，不做方向融合。
- **新损失：** 无。

### 运行安排（2026-11-13）

- **服务器：** 旧服务器 GPU 0、1，配置 `configs/deim_dfine/deim_hgnetv2_m_sardet100k_fine_level_36e_b32_old_server.yml`。它与旧服务器的 E000 配置只差本模块、输出目录和协议文档字段（单元测试检查）。两台服务器的同一基线相差约 0.4 AP（SAR-AIRcraft 上的经验），所以**只与 E000-old 比较**（val AP 65.15，运行目录 `/data2/zxy/sar/experiments/deim_m_sardet100k_deim_hgnetv2_m_sardet100k_36e_b32_nozoom_nocrop_seed0_20261107_083221_byTPNu`）。上面判定表中的 E000 数字相应换成 E000-old。
- **参数量：** 19,799,390，比 E000 多 323,360。
- **显存（2026-11-14 修正）：** 第一次启动在旧服务器上显存溢出（GPU 1：23.52 GiB 中已分配 22.45 GiB，出错位置在 decoder 的可变形注意力）。原先“约 21.7 GB”的估计偏低：它只按 CPU 上为反向保存的张量比例从 E000 的峰值推算，没有覆盖 AMP 下的实际分配。随后在 8 卡服务器空闲的 RTX 4090 上实测一步训练（batch 16、800×800、AMP、单卡）：E000 14.8 GB，E015（只对精细层做检查点）20.4 GB。E000 正式训练日志的峰值是 18.2 GB，比单卡单步多约 3.4 GB；照此推算 E015 约 23.8 GB，与溢出一致。
- **修复（`fine_checkpoint: True`，只改执行方式，不改结果）：**
  1. 精细层的块在反向时重算，重算时使用临时 BN/SyncBN 滑动统计缓冲区（与 E013-v2 相同），每步只更新一次滑动统计；
  2. 对全部 token 的 encoder 输出打分（Linear、LayerNorm、分类 Linear，没有 BN 和随机性）在反向时重算；
  3. decoder 的多尺度 value 每层只保留一份连续拷贝，6 层共用。原实现里每层可变形注意力的 reshape 都会复制全部层级并各自为反向保存，stride-4 层有 40,000 个 token（800 输入），这部分最大。
  单元测试核对了：打开与关闭这三项时，整模型训练前向的输出、全部参数梯度、BN 缓冲区一致。服务器 CPU 上为反向保存的张量（800 输入、batch 2、fp32）：E000 2.87 GiB；E015 不做节省 4.62，做 1、2 后 3.32，再做 3 后 3.02。按两次 GPU 实测换算，单卡单步约 16.3 GB，正式训练约 19.7 GB，在 23.5 GiB 卡上留出约 4 GB。完成修复后没能再上 GPU 实测（卡被占用），以启动后日志的 `max mem` 为准。代价是精细层和打分多算一次前向。
- **新服务器配置**同样打开了检查点，两者模块设置一致。

### 与另外两个方法的分工

| | RegionDenseSAR（辅助） | E013-v2（主线） | E015（第三个） |
|---|---|---|---|
| 网络中的位置 | 训练样本构成 | 骨干与投影特征 | neck 的最细层、query 来源、decoder 采样 |
| 解决的问题 | 尺度、密度与背景相容 | 方向锁定、无副本目标打分 | 极小目标在 stride 8 下的分辨率不足 |
| 图像层面的依据 | 拼图缩小目标有害（D12） | 成像几何的上下不对称（D17、D18） | 尺寸断崖、无候选、格内相位误差（D25、D26） |

RegionDenseSAR 让训练中有更多保持原尺度的小目标，E015 让网络有能表示它们的分辨率，两者对小目标是互补关系，不重复。

### 判定（训练前写定）

| 项 | 标准 |
|---|---|
| 主指标 | 相对 E000 的 val AP ≥ +0.5 |
| AP50 | 不低于 E000（93.15） |
| 机制 1 | tank 与 bridge AP 合计 ≥ +2，主要来自 OGSOD |
| 机制 2 | 原图长边 < 16 的 tank、bridge AP 上升；D26 的“无候选目标”从 245 个下降 |
| 机制 3 | OGSOD tank 的格内相位周期幅度（D25 口径）下降 |
| 副作用 | APm、APl 下降不超过 0.5 |
| 证伪 | AP 涨幅 < 0.5，或极小目标不涨 |

### 校准

- **它是标准结构。** stride-4 层（P2）在小目标检测中常见，论文不能把结构本身写成创新；可写的是“由 SAR 极小目标的诊断引出、并与成像几何和尺度保持数据组成一个整体”。SAR 特有的稀疏峰值版本已被 D29 否定。
- **主观估计（没有实验依据）：** 涨幅 ≤ +0.3 约 40%，+0.3–1.0 约 30%，> 1.0 约 30%。比 11-06 时略乐观，因为 E013-v2 表明冻结检验会漏判训练后的收益。
- **代价未测：** 25,600 个额外 token 会增加 query 选择和 decoder 采样的显存与时间；与 E013-v2 组合时骨干本来就要跑两次。启动后先看显存。
- **旧的负结果：** HWD 和 S2 注入只把细节加进 stride 8，输出仍是 8/16/32，且是在 OGSOD 或 SAR-AIRcraft 上测的，与这里不同。
- **待 E013-v2 结束后再确认一次：** 方向融合可能已经提高一部分 OGSOD tank（D17 中 tank 的方向效应最大）。届时用 E013-v2 的权重重算尺寸分组 AP 和 D26 的无候选目标数；若极小目标的缺口已大部分消失，E015 的必要性要重新评估。

## 局限

- D28、D29 只用了 E000，单种子。
- D28 的“在排上”是手工定义的两种几何关系，不覆盖弯曲排列或二维网格的对角关系；重打分规则是学习式关系模块的弱替代。
- D29 的峰值是手工 CFAR 规则，不代表学习式的稀疏选择也无效。
- 第一节的比较用的是 E013-v2 训练中途的验证结果，最终差距要等训练完成。
