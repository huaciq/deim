# SARDet-100K E000：来源 × 类别评测（val）

本文回答“按类别看 AP 掩盖了什么”。所有数字来自 E000 已保存的 val 预测，没有新训练，也没有使用 test。

## 主要发现

1. **类别 AP 确实掩盖了来源差异。** Tank 全局 57.7，拆开是 OGSOD 30.6、MSAR 95.2、other_512 82.6。Bridge 全局 46.0，实际约等于 OGSOD bridge（45.0），因为 97.2% 的 bridge GT 来自 OGSOD。
2. **“OGSOD 难”也不准确。** 同在 OGSOD，harbor 的 AP 是 80.5，≥128 像素的目标 AP 是 90.3。难点是其中的小目标 tank 和 bridge。
3. **错误集中在少数单元格。** OGSOD tank、OGSOD bridge、other_512 aircraft、other_256 ship、other_800 ship 占 GT 的 75.4%，占漏检的 91.1%，占背景误检的 78.5%。其中 OGSOD tank 和 bridge 只占 GT 的 19.6%，却占漏检的 50.8%。
4. **这几个单元格的失败方式不同：**
   - **OGSOD tank/bridge：** 小目标，定位和漏检都差。tank 的 AP50 是 78.2，AP75 只有 17.3。
   - **other_512 aircraft：** 不是小目标问题。32–64 像素 AP 72.7，64–128 反而降到 60.7，≥128 为 60.1。误检中 Loc 198、Dupe 176，漏检中 NoBox 146。
   - **other_256 ship：** 能找到但框不准。AP50 97.7，AP 只有 69.3。
   - **other_800 ship：** 背景误检最多的单元格（462），其中 383 个预测框长边 < 32 像素。
5. **尺寸解释不了全部差异。** 输入长边都在 32–64 时，tank 的 AP50 几乎相同（OGSOD 99.9、MSAR 98.6、other_512 99.8），AP75 却是 62.4、96.5、96.4。OGSOD 这一格只有 52 个 GT，只能作为线索。同样在 32–64，ship 的 AP 是 MSAR 81.4、other_800 82.6、other_256 59.3。
6. **跨来源的分数校准不像主要问题。** 全局类别 AP 和各单元格按 GT 加权的 AP 很接近：ship 73.7 对 73.4，aircraft 62.8 对 63.2，bridge 46.0 对 46.0，tank 57.7 对 54.8。

### 局限

- val 与 train 有大量近重复，MSAR 等分组的高 AP 可能偏乐观，本文没有按重复程度拆分。
- 来源、尺寸、对比度、背景在数据中相互纠缠，表中的差异都是相关，不能当作因果。
- OGSOD tank 中位长边约 8 像素，1 像素偏移就可能让 IoU 低于 .75（双轴各偏 1 像素时 IoU≈.62）。AP75 低可能部分来自标注精度极限，这一点尚未验证。

## 口径

- **模型：** E000（`best_stg2.pth`），val 共 10492 张图、22703 个 GT。
- **评测实现：** 与训练相同的 `faster_coco_eval`。全局结果复现为 AP 65.29 / AP50 93.14 / AP75 70.27。
- **分组：** OGSOD、MSAR 靠像素比对识别；其余按图像尺寸分组，`other_*` 不等于单一来源。
- **单元格 AP：** 只用该分组的图像和预测评测，是独立的 AP，不是全局 AP 的分量。
- **Recall：** `Recall` 是工作点（score ≥ 0.3，IoU ≥ 0.5）的召回，1 − Recall 对应漏检数。`R50` 是不设分数阈值、每类最多 100 框时 IoU .5 的召回。
- **错误数：** 工作点下贪心匹配，分类规则与 `error_gallery.py` 相同。总数和该脚本一致（TP 21332，FP 3735，FN 1371）。
- **背景误检：** 预测框与所有 GT 的 IoU 都 < 0.1。
- **尺寸：** 按框长边。“原图”是标注像素，“输入”是长边缩放到 640 后的像素，后者更接近模型实际看到的大小。
- **小样本：** `*` 表示该单元格 GT < 100，AP 波动大，不宜单独下结论。`—` 表示没有 GT，AP 无定义。
