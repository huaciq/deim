# D9 Query 身份演化：分类分差与匹配身份，谁先变

问题：同一个 tank GT 的两个竞争 query，一个框更好、另一个分数更高。训练中是**分类分差先扩大、导致匹配改变**，还是**匹配先改变、导致分类分差扩大**？同样的匹配机制，为什么 MSAR 正常、OGSOD 锁错？

不训练、不改结构，只用 CPU。E000 的全部 9 个 EMA 检查点（第 3、7、11、15、19、23、27、31 轮和第 35 轮 `best_stg2`），val 中 OGSOD 与 MSAR 的 tank 图。

（上一轮的“候选框取共识”检验原来编号 D9，已改为 [D8.3](sardet100k_d83_box_consensus.md)，服务器目录名 `d9_consensus` 不变。）

## 口径

### 跨检查点的身份

Decoder 第 j 个 query 由 encoder Top-300 的第 j 个 token 构造，token 是 encoder 特征图上固定的位置（层级 + 网格）。query 序号跨检查点不可比，token 可比。所以**用 token 作为 query 的身份**：某个检查点上该 token 不在 Top-300 时，这个 query 不存在（没有 decoder 输出，也不能被匹配），但它的 encoder 分类 logit 仍然有定义。

### 竞争对（在第 35 轮定义一次）

- 候选：以该 GT 为最大 IoU 的 tank GT、且 IoU ≥ .1 的末层 query。
- A = 分数最高的候选（最终赢家）；B = A 以外 IoU 最高、且 IoU ≥ .5 的候选。
- **wrong：** IoU(B) ≥ IoU(A) + .05，赢家是更差的框。对应 tank 诊断的“480 对”，这里得到 464 对（75 张图）。
- **right：** IoU(A) ≥ IoU(B) + .05。**tie：** 其余。

### 每个检查点、每个阶段（enc、pre、dec1–4）记录

- 匹配身份：用该运行的 matcher 对图中全部 GT 匹配（与训练相同），这个 GT 给了 A / B / 其他 / 没有。
- A、B 的 tank logit、IoU、加权后的匹配代价项（分类 × 2，L1 × 5，GIoU × 2）。代价计算已与 matcher 的代价矩阵逐项核对（最大误差 3e-7）。
- A、B 在 tank 通道上的 MAL 目标与权重：被匹配为 IoU^1.5 与 1，否则为 0 与 p^1.5。
- 分类项是否决定了两者的偏好：框代价偏向一个，总代价偏向另一个。
- 第 4 层上分数最高、IoU 最高的候选分别是谁。

### 先后顺序的判定

- **分数领先：** 第 4 层 logit(A) > logit(B)。B 不在 Top-300 算 A 领先，A 不在算不领先。
- **匹配锁定：** 第 4 层匹配给 A。
- **锁定轮次：** 从该检查点起到第 35 轮一直成立的最早检查点。
- 比较两者的锁定轮次，分为分数先、匹配先、同一检查点、未锁定。另外统计相邻检查点间的转换：匹配转到 A 之前分数是否已领先；分数转为 A 领先之前匹配是否已在 A。

## 判读

### D9.1–D9.2：分数先，匹配后

1. **分数领先先形成，匹配之后才跟上。** OGSOD wrong 中，分数先锁定的占 40%，匹配先锁定的只有 1%；锁定轮次中位数分别是第 19 轮和第 27 轮。
2. **分数转向 A 几乎从不发生在 A 已被匹配之后**（3.3%，基准率 34.7%）。A 的分数优势不是靠“自己是正样本”得来的。
3. **前 19 轮，匹配器其实更常选 B。** 第 3–19 轮，B 在第 4 层被匹配的比例（33–36%）高于 A（20–30%）。框代价在约 70% 的对里偏向 B（GIoU 代价差 −.31 到 −.37），分类项只在 11–19% 的对里决定偏好。按这些 GT 的匹配，前期大约一半的对里 B 会得到 MAL 正目标、权重 1。
4. **即便如此，A 的分数从第 3 轮起就略高**（logit 差 +.12，64% 的对 A 领先），encoder 上也一样（+.14）。框质量差在整个训练中基本不变（IoU 差约 −.13 到 −.16）。
5. **转折在第 19–23 轮之后。** logit 差从 .27 跳到 .66、1.55、3.11、4.26；分类代价差从 .14 涨到 2.30，超过 GIoU 的约 .33；分类项决定偏好的比例从 .19 涨到 .81。匹配随之从 B 转到 A（A 从 .30 到 .79）。“匹配离开 A”时，92% 的分数仍是 A 领先，说明分差还小时框代价能把匹配拉回 B；分差变大后就拉不回来了。
6. **转折恰在第 20 轮的训练日程边界上：** 这一轮 Mosaic 与 MixUp 关闭（Dense O2O 结束），同时 flat 学习率结束、进入余弦衰减。两者重合，这一轮数据分不开；后文 E008 对照表明对应的是增强关闭。

所以，对“谁先变”的回答是：

- **这对 query 在这张图上的匹配，不是分差的原因。** 分差从一开始就存在，而且在 A 不是正样本的时候也在增长。
- **分差越过框代价之后，它决定了匹配。** 这之后，匹配与 MAL 一起把分差推大：第 23 轮后 B 的 MAL 权重降到 .08 以下，B 不再有梯度。

### 一个必须写明的限制

**这些都是 val 图，模型从未在它们上面训练过。** val 上的“匹配”和“MAL 目标”描述的是“如果这张图在训练集里，损失会怎样”，它们不可能是 val 上分差的原因。

所以第 2 点的含义更强：A 的分数优势完全来自模型在训练集上学到、再泛化过来的偏好，即分类分支对“这种外观更像 tank”的判断。D8.1 看到的“分数偏爱包住最亮像素的框”就是这种偏好的一个表现。这些 val GT 自身的匹配不参与它。

要看被监督样本上的真实先后，需要在训练图上做同样的重放（模型见过这些图，只是没有增强）。

### D9.3：为什么 MSAR 正常

| | MSAR right | OGSOD wrong |
|---|---|---|
| 第 3 轮的 logit 差（dec4） | **5.7** | .12 |
| 第 3 轮第 4 层匹配给 A | .77 | .20 |
| 锁定轮次（分数 / 匹配） | 3 / 3 | 19 / 27 |
| 分数最高 = A（第 3 轮） | .77 | .28 |
| A、B 的 IoU 差（dec4） | +.04 到 +.14 | −.13 到 −.16 |

- **MSAR 在第一个检查点之前就分出胜负了。** 第 3 轮 A 已领先 5.7 个 logit，之后单调增大；匹配、最高分、encoder 匹配都从一开始指向 A，并一直不变。分数领先和匹配锁定在 84% 的对里落在同一检查点。
- **MSAR 的竞争者从来不是势均力敌的。** B 的分数远低于 A，同时两者的框都很好（IoU 差只有 .04–.14），所以“分数选谁”几乎不影响定位。
- **OGSOD 的两个候选在前 19 轮分数几乎一样**（差 .1–.3 个 logit），分类分支分不开它们，框代价让匹配器偏向更好的 B。日程边界之后，分差被放大，而放大的是一开始就略微领先、但框更差的 A。
- **OGSOD right 的轨迹与 wrong 几乎相同**（早期差 .15，第 19 轮后放大），只是一开始领先的恰好是好框。哪一个被放大，取决于第 3 轮就存在的那点微小偏好，而这个偏好与框质量无关（D7–D8：分不清谁更准）。

**结论：** 同样的“分数决定匹配、匹配强化分数”的机制，在 MSAR 上一开始就有清楚的分数差，而且分数高的就是好框，所以锁定是对的。在 OGSOD tank 上，分类分支在前期分不开两个候选，后期的放大把一个与框质量无关的微小初始偏好固化下来。

### 判读

1. **训练图上的结论与 val 相同。** E000 训练图 3,193 对：分数先锁定 39%，匹配先 1%；分数转为 A 领先时，前一个检查点已匹配给 A 的只有 4.4%（基准 35.6%）。所以“分数先、匹配后”不是 val 未参与训练造成的。
2. **在受监督的图上，前期这些 GT 的匹配大多偏向更好的框 B，A 的分数仍然领先并增长。** 第 3–15 轮，按这些训练图的重放匹配，52–58% 的对里 B 是 MAL 正样本（权重 1），A 的目标是 0；但 A 的 logit 一直领先（.15–.22），而且 64–73% 的对 A 领先。分类分支的偏好不是这些实例自身的匹配教出来的，而是在整个训练集上学到、按外观泛化的偏好。
   - 注意：这是不加增强的 EMA 重放。真实训练 batch 有 Mosaic、MixUp 和多尺度，同一 GT 当时的匹配可能不同。
3. **转折不是学习率造成的。** E008 的学习率日程与 E000 相同，但分差放大提前了约 8 轮：logit 差在第 11 轮已到 .33，第 15 轮 .73；E000 要到第 19 轮 .33、第 23 轮 .73。锁定轮次中位从第 19 / 27 轮提前到第 7 / 19 轮。所以 E000 第 20 轮的转折对应的是 Mosaic/MixUp 结束，不是学习率进入余弦衰减。
4. **Mosaic/MixUp 推迟了锁定，但不是锁错的原因。** 关掉它们后锁定更早，“分数先”的比例更高（.50–.55），错误锁定仍然大量存在。不过错误锁定的对确实少了：E000 训练图 3,193 对、E008 2,326 对，样本是同一批 612 张 OGSOD 样图，对的定义也相同，少了 27%。这与 E008 的 tank AP +1.57 方向一致，但没有单独验证二者的关系。
5. **对 MSAR 的结论不变。** E000 训练图上，MSAR 赢家框更好的 1,737 对第 3 轮已领先 5.7 个 logit，分数与匹配都在第 3 轮锁定。E008 上 MSAR 的对几乎全是 IoU 相差 < .05 的平手（3,111 对，赢家框更好的只有 11 对），谁赢都不影响定位。

### 更新后的结论

1. OGSOD tank 的错误锁定由分类分支的初始偏好决定。这个偏好在第 3 轮已存在，与框质量无关，也不来自这些实例自身的匹配；它是在整个训练集上学到的外观偏好。
2. 偏好被放大的时机由 Dense O2O 控制：有 Mosaic/MixUp 时推迟到它关闭的第 20 轮，没有时从第 7–11 轮开始。分差越过框代价之后，匹配才转到赢家，此后匹配与 MAL 把它固化。
3. 在受监督的图上，“匹配先变、导致分差扩大”这条路径几乎不出现（1–2%）。所以只改匹配（E004）不能改变锁定的对象，它只改变了 MAL 正样本给谁，而分类分支的外观偏好不会因此改变。这与 E004 的结果一致。

## 局限

- EMA 权重、无增强的重放，不是训练 batch 上的真实分配。val 上的匹配和 MAL 不产生梯度，只描述状态；训练图上更接近真实，但仍然没有 Mosaic/MixUp 与多尺度。
- 训练图的来源按 tank 尺寸划分，不是像素比对（val 上一致率 139/140）。
- 检查点相隔 4 轮。“同一检查点”占 38%，这部分的先后无法区分。
- E000 第 20 轮的增强关闭与学习率转折重合；E008 对照把它归到增强，但 E008 本身就是另一次训练（单种子），不是同一训练只改一处的干预。
- 对在第 35 轮定义，带有选择偏差：wrong 组按定义以 A 领先结束。早期 A 已领先（64%）这一点不受此影响。
- 单种子。
