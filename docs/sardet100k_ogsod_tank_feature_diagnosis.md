# SARDet-100K：OGSOD Tank 特征表达诊断

本文定位 E000（DEIM-D-FINE-M）在 OGSOD Tank 上 AP 只有 30.6 的原因。只用 val，没有改模型、没有重新训练、没有设计新模块。

## 结论

1. **AP 低主要是框不够准，不是找不到。** AP50 78.2，AP75 17.3。漏检只影响一部分；即使检出，TP 的 IoU 中位数也只有 0.71（MSAR 0.97）。
2. **两类失败要分开看：**
   - **漏检（246 个）** 在 Encoder 输出时基本已成定局，Decoder 既没有造成也没有挽救。目标本身的证据弱、尺寸小、排列密，是相关性最强的因素。
   - **框不准** 随尺寸变大也不消失：同为输入 32–64 像素时，AP50 与 MSAR 相同（99.9 对 98.6），AP75 却是 62.4 对 96.5。标注精度能解释一部分，解释不了全部。
3. **没有证据表明存在单一的"损坏环节"。** 从 Backbone 到 Neck，目标的线性可分性是上升的，没有哪一级把已有的证据丢掉。Neck 对命中目标放大很多，对漏检目标放大很少，但这不能证明 Neck 是原因。
4. **漏检高度集中，而且和"见没见过这个方向"强相关。** 8 张图（共 82 张）占 67% 的漏检。同一张图翻到训练集里有的方向，召回从 0.392 升到 0.760；翻到训练集里没有的方向，从 0.836 降到 0.552（第 7 节）。所以 AP50 78.2 有相当一部分来自训练集的重复图块，实际泛化能力低于这个数字。
5. **MSAR 不是公平的参照。** 两者是外观不同的目标：MSAR 是 30 像素的环状强散射、暗背景；OGSOD 是 5–9 像素的无结构亮斑、亮背景。把 MSAR 缩到相同输入尺寸后，它的 AP 从 95 掉到 26–76（有尺度失配，见表 8）。
6. **OGSOD 的镜像副本之间，标注和像素差恒定的 2 个原图像素。** 32 对图没有例外（第 7 节）。这和已知的 x 向偏移、y 向几乎没有偏移的现象一致，并可能给 8 像素目标的 IoU 设了约 .78 的上限。

> **更正：** 本文初版根据只含平移的布局匹配，认为存在"没见过的场景"，并认为"成败由场景决定"。八方向匹配后，这两点都不成立：`0036526`、`0091189` 就是 `0112914` 旋转 180° 后的图块。下文第 3 节表 4 的"见过/没见过"和表 1 的"场景"列仍是旧定义，只保留作记录，请以第 7 节为准。

响应分三层，统计只用前两层：**原始特征**（Hook 到的 C×H×W 张量）、**通道聚合**（每格 L2 范数；另存平均绝对值）、**可视化归一化**（只用于显示）。

- **Hook 点：** S2（stride 4）、P3/P4/P5（Backbone）、F3/F4/F5（Neck 输出）、M3/M4/M5（`enc_output`）、T3/T4/T5（Encoder 头的 Tank 概率）。
- **Decoder 各层：** 运行时把已加载对象的 `eval_idx` 设为 0–3，磁盘上的代码和权重不变。
- **GT 与周边的取值：** 按特征格与区域的重叠面积加权，因为 stride 32 下一个 20 像素的框还不到一格。周边环的 guard = max(side/4, stride/2)，宽度 = max(side, 2·stride)，其他 GT 从环中扣除。

响应大小不等于语义重要性，所以判断环节时主要依据后面的预测行为（表 4、5）、线性探针（表 6）和输入尺寸对照（表 8）。

### 看图的观察

这些是主观判断，用来提出假设，不作为证据。

- **MSAR：** 目标是大尺寸环状结构，P3 能描出轮廓，T5 在每个目标中心只亮一格，极干净。
- **OGSOD 命中：** 规则排列的亮斑，T3 成团响应，F3 在目标群上明显成片。
- **OGSOD 漏检：** 目标更弱、更靠近亮杂波。部分 GT 位置在输入里看不出明确的目标（例如 `ogsod_miss_07`、`ogsod_miss_09`）。这些位置常有大片低分框（.05–.3），是一团不确定的响应，不是完全没有响应。

## 4. 定位错误原因

| 环节 | 判断 | 依据 | 反面或局限 |
|---|---|---|---|
| **输入本身** | **主要约束之一**（中等把握） | SCR 0.2–0.3 dB 对 MSAR 1.7 dB；背景饱和更多；无内部结构；原图 5–9 像素；OGSOD 内部召回随尺寸变化最大（表 9） | SCR 未定标；相关不等于因果；部分 GT 看不出目标，可能源于标注 |
| **Backbone 早期** | 不是单独的断点（中等把握） | 漏检的探针 AUC 已有 .78–.79，随层上升，没有丢失；同尺寸下 input/S2 的 hit-miss 差异小（.57–.59） | 线性探针有局限；MSAR 的 S2 探针也只有 .71，所以"早期可分性低"本身不必然导致失败 |

| **Neck 融合** | 不是丢失证据的地方，但放大不均（中等把握） | 探针上升而非下降；F3 是 hit-miss 最大的跳升；命中被放大到近 1.0，漏检只到 .85 | 这可能只是把已有差异放大。没有改模型的反事实，无法判断换一种融合是否会改变结果 |

### 可能的机制

按证据强弱排序，都是解释，不是已证明的因果。

1. **小目标的 IoU 对亚像素误差极度敏感。** OGSOD 目标中位 8 像素，dx、dy、dw、dh 都只有约 0.25–0.55 像素的 MAD，已经是亚像素水平，IoU 却只有 .71。这解释 AP75 的绝大部分：框的绝对误差不大，但相对误差比 MSAR 大一个数量级（相对 MAD .03–.07 对 .004–.01）。
2. **标注精度和偏移拉低了上限。** 整数坐标加上已记录的 +0.8 像素 x 向偏移（`sardet100k_baseline_diagnosis.md`），IoU ≥ .75 的上限就可能降到 56% 左右。第 7 节进一步给出来源：镜像副本之间标注恒差 2 像素。
3. **目标在杂波中缺少判别结构。** OGSOD 目标是对比度很低的亮斑，局部环境亮且部分饱和。Neck 之后 FP 和命中只有 .74–.79 的可分性，漏检更不像目标。于是分数整体偏低且分布挤在一起，工作点附近容易掉出。
4. **弱目标得不到 Neck 的放大。** Neck 大幅提升强目标的可分性，弱目标提升很少，后续分数继承了这个差距。不确定这是原因还是结果。
5. **成败和方向的熟悉程度有关，和噪声版本关系不大。** 同方向的平滑版和斑点版召回基本一致（表 11），不同方向的同一图块却可以差很多（第 7 节）。初版的"成败由场景决定"是错的。

## 5. 尚无法确定的问题

1. **部分 GT 是否真的能从 SAR 图上看到。** 有些漏检位置肉眼也看不出目标。如果标注依赖光学参考，这部分漏检可能无法靠 SAR 外观解决。OGSOD 的标注流程还没有读到原文。这也关系到 `0036526`/`0091189` 这个场景为什么失败。
2. **FP 是否是未标注目标。** 背景误检（238 个）在特征上和命中接近（.74–.79），未核实。
3. **真正没见过的场景上表现如何。** 80/80 张（≥ 3 个 Tank）OGSOD 图的布局都能在 train 按某个方向重现，所以 val 里没有新场景。第 7 节只能测"见过的场景、没见过的方向"，完全新场景上的表现无法从现有 val 得到，只能更差或相近。
4. **MSAR 95.2 是否也偏乐观。** 按缩略图，MSAR 只有 3/58 有近重复（≥ .9），但 90% 的 GT 布局能在 train 重现；布局匹配对大目标有偶然匹配的可能。垂直翻转后 MSAR 的 TP IoU 从 .969 掉到 .837，Encoder 概率几乎不变（.915 → .911），原因未查明，MSAR 标注是否有类似偏差也没有核对。
5. **下采样的独立作用。** 尺寸扫描被模型的尺度依赖掩盖，没有分离出来。在不改模型、不重新训练的约束下，本文无法回答这个问题。
6. **Neck 差异放大是因还是果。** 需要反事实才能回答，当前约束下做不到。
7. **T3 的 x 向条带。** 在命中目标周围，T3 ±1 格的响应 x 向（.138 / .195）是 y 向（.055 / .063）的 2–3 倍，而 F3、P3 的响应基本对称（F3 x 向 5.88 / 6.05，y 向 5.84 / 6.05）。看起来各向异性出现在分类头这一步，并且偏向 +x，和已知的 x 向偏移方向一致。但排成横行的目标也可能造成这个现象，孤立目标只有 8 个，无法排除。
8. **FP 的 z 和漏检的对比** 受选择偏差影响（FP 是模型挑出的），不能当作外观比较的直接证据。
9. **2 像素差的绝对分配。** 无法判断是每张图各偏 1 像素，还是只有部分副本偏 2 像素（见第 7 节）。train 内的副本已直接核对，关系相同（见表 15 的全量核对）。

### 四个问题的回答

**A：为什么成功？** Encoder 这一步已经决定了：GT 内的格子概率 .449，排第 12 名，框的 IoU 已有 .699。Decoder 只有两个作用：把分数从 .449 提到 .527，以及压低重复框（旁边的 Query 35 从 .352 降到 .107；同样覆盖 GT 的 Query 146 IoU .669，但分数只有 .075）。框本身没有被修正，IoU 反而从 .699 降到 .686。

Backbone 响应也解释不了成功：P4、P5 的 z 都是负的。更重要的是，同一目标旋转 180° 后就不再被检出（概率 .138），旋转后的斑点版概率只剩 .018。所以这个成功至少部分依赖"见过这个图块的这个方向"。

**B：为什么框不准？** 这个样本的主要问题是**框太大**：GT 是 4×3 原图像素，预测约 6.4×5.4。这个误差在 Encoder 就有了（dw +2.60，dh +2.42），Decoder 只修正了位置（dx 从 +2.20 到 +.93，IoU .241 → .349），大小完全没变。5 个 IoU ≥ .1 的 Query，IoU 都在 .35 左右，都没能给出合适的大小。

这个样本比同类更极端。同类 32 个的中位数是 dw +.61、dh −.10、dx +.90，GT 长边中位数 5，所以多数情况更像"小目标上的位置偏差"，而不是框太大。这 32 个中有 37.5% 的高分框其实离另一个 GT 更近。

**C：为什么框对了分数低？** 不是响应弱。C 的 F3 响应是四个样本里最强的（z 3.01，比成功的 A 高），但 Encoder 概率只有 .178（这个 Query），排名 159。Decoder 把分数提到 .265，没过 .3。

- **分类头是主因。** 最后一层原始 logit −.81，LQE −.21。总体上 LowScore 与 TP 的原始 logit 差 1.67（−1.08 对 .586），LQE 只差 .11（−.243 对 −.131）。
- **这个样本还有邻居干扰。** GT 内排名更高的格子（Query 77）把框回归到了左边的邻居（与 GT 18967 的 IoU .499，分数 .494）。但这只占 LowScore 总体的 4%，不是一般情况。

**D：为什么 Encoder 没选出合适候选？** 不是名额被抢，是这个位置根本没被当作 Tank。GT 内最高概率 .0016，比入选线 .101 低 60 多倍，排名 3099。把 K 扩大几倍也选不到。

但回归分支其实能给出还不错的框：这个最佳格子的框 IoU 有 .595。F3 的 z 也有 1.54，接近 A。所以断点在 **Encoder 的分类**，不在定位，也不在选择机制本身。Query 选择只按类别分数排序，分类分低，好框就进不来。

这个 GT 在两个方向上都失败，概率都接近 0。肉眼看，它位于一大片亮区内部，看不出独立的目标（主观判断）。所以它可能是真正的难例，也可能依赖其他模态的标注，这一点无法从 SAR 图判断。

同类总体：58 个 GT 内没有入选格的 NoBox，最佳排名中位数 1258，其中 26 个进入前 1000。

### 四个样本的共同点

1. **响应强度和判定对不上。** F3 z 的顺序是 C > A > D > B，Tank 概率的顺序是 A > C > B > D。D 的 F3 z（1.54）接近 A（1.68），概率却差 280 倍。L2 范数不足以说明模型是否认为这里有目标。
2. **成败在 Encoder 就基本确定。** 跟踪的三个 Query 经过 Decoder，IoU 变化最多 +.11（B），Tank 分数变化最多 +.09（C）。
3. **都有 x 向正残差。** A、B、C 的 dx 分别是 +.98、+.93、+1.42。A 和 C 明显大于 dy，B 和 dy 接近（+.81）。三个样本不足以下结论，但方向和第 7 节的分析一致。

- **确定的：** 像素对得上，标注差恒定 2 像素，且只出现在翻转的轴上。如果偏移是成像物理造成的，它应随图像翻转，这个差值应为 0。所以这 2 像素来自**标注或数据处理**，不是物理现象。这回答了 `sardet100k_baseline_diagnosis.md` 里"物理原因未证实"的一部分。
- **不确定的：** 只凭配对无法判断是每张图都偏 (−1, −1)，还是只有部分副本偏 2 像素。两种情况产生相同的差值。

**影响：** 水平翻转增强得到的图，和数据集里已有的左右翻转副本，像素相同，标注却差 2 像素（train 内已直接核对）。同样的输入有两个相距 2 像素的答案，模型最多只能取中间，与每个答案差 1 像素。仅这一项，8 像素目标的 IoU 上限约为 7/9 = .78，6 像素约 .71，5 像素约 .67，和实测 TP 中位数 .71 同一量级。这也和样本 A、B、C 的 x 向正残差，以及 y 方向残差接近 0（训练没有上下翻转增强）一致。

## 9. LQE 与候选排序（2026-11-08）

E000，OGSOD 与 MSAR 全部 val 图（1,834 / 1,409 张），一次前向，权重不变。脚本 `tools/sardet100k/tank_lqe_ranking.py`，结果在 `independent_verify_20261106/tank_lqe_ranking/`。散点图在本地 `analysis_outputs/tank_lqe_ranking/score_iou_scatter.png`（不进 Git）。

### 代码路径（读代码确认）

| 问题 | 实际情况 | 位置 |
|---|---|---|
| LQE 的输入 | 四条边回归分布各自的前 4 个概率及其均值（20 维），经 2 层 MLP 得到一个标量；不看图像特征 | `dfine_decoder.py` `LQE.forward` |
| LQE 如何使用 | 这个标量加到全部 6 个类别的 logit 上 | 同上，`scores + quality_score` |
| LQE 的监督 | 没有单独的损失，只通过 MAL 间接训练；MAL 作用在相加后的 logit 上，目标为匹配框 IoU 的 1.5 次方，未匹配为 0 | `deim_criterion.py` `loss_labels_mal`，配置 `gamma: 1.5` |
| 是否参与 Encoder Top-K | 不参与，Top-K 只用 `enc_score_head` 各类最大的 logit | `_select_topk` |
| Decoder 推理 | 只计算最后一层（`eval_idx`），只用该层的 LQE | `TransformerDecoder.forward` |
| 最终分数 | sigmoid(分类 logit + LQE)，在 300 query × 6 类中取前 300 | `postprocessor.py` |

4. 局限：82 张 tank 图；按 val 比较了几个固定的组合权重，没有做调参，选最好的一个也会偏乐观；Oracle 没有去重。

## 10. Query 逐个追踪与重复框（2026-11-08）

## 11. 逐层追踪：失配从哪一层开始（2026-11-08）

E000 的 Decoder 有 4 层。推理时只计算 `eval_idx` 一层，所以对每张图前向 4 次，分别把已加载对象的 `eval_idx` 设为 0–3，取出每层的分类 logit、LQE 和框；磁盘上的代码和权重都不变。

- **同一批 query：** 每次前向都断言 Encoder 选出的索引完全相同；最后一次与默认前向的输出最大差为 0。
- **口径固定：** 每个 query 的 GT（它在任一阶段重叠最多的 tank GT）和候选集合（任一阶段 IoU ≥ .1）只确定一次，各层不重选。
- **分数：** 各层分数 = 该层分类 logit + 该层 LQE；Encoder 没有 LQE。
- 脚本 `tools/sardet100k/tank_layer_tracking.py`，结果在 `independent_verify_20261106/tank_layer_tracking/`。

1. **失配从 Decoder 第 1 层开始。** OGSOD 上，分数与 IoU 的相关从 Encoder 的 .384 降到第 1 层的 .180，第 2 层最低（.110），后两层回升到 .244，但没有回到 Encoder 的水平。MSAR 只在第 2 层下降，最后回升到 .705，超过 Encoder。
2. **C 类的框主要在第 1 层变差。** 总降幅 .072 中有 .048 发生在第 1 层，分数则在第 1、2 层上升最多。这不是 6 层逐步恶化的形态，而是前两层就基本定型。
3. **错误排序在 Encoder 就已存在，Decoder 把它放大了。** 480 对中，88% 在 Encoder 阶段就是差框分数更高。Decoder 没有纠正这个排序，反而把分数差从 .22 拉大到 .54；更好的框 IoU 继续上升，却被压成背景（.151 → .02）。这符合一对一匹配“保留高分者、压制重复”的行为，但它保留的恰好是差框。
4. **后两层只改分数、不改框，这种更新与框质量无关。**
5. 局限：140 张图；4 层模型的结论不能直接外推到更深的 Decoder；“被判为背景”的 query 多数是正常被压制的重复框。

### 其他统计

- **每层都会重新匹配。** 4 个 Decoder 层匹配到同一个 query 的占 76.2%。
- **最常见的匹配序列（Encoder、pre、D1–D4）：**
  - 全部为第一名：227 对；

  - 仅 Encoder 匹配更好的框，之后都是第一名：37 对；

- **框监督的并集：** 第一名在其中的占 81.9%，更好的框占 39.4%，每个 GT 的并集 query 数中位数为 1。更好的框在任何阶段都没被匹配的占 60.6%。
- **分类监督（MAL）：** 更好的框在 4 个 Decoder 层的目标都是 0 的占 69.6%，在最后一层为 81.0%。约 20% 的对（39.4% − 19.0%）中，更好的框在最后一层同时受到框回归监督（来自并集）和背景分类监督。

1. **按框的质量，更好的框应当被匹配；按分类，它不会被匹配。** 在 Decoder 2–4，更好的框的 L1+GIoU 代价几乎 100% 更低（GIoU 代价低约 .33），但分类代价高 2.2–2.4。分类项在总代价里占了上风，81% 的对因此把正样本给了框更差的那个 query。
2. **这个偏好随层加深而加强：** 分类代价差从 Encoder 的 .61 增加到 Decoder 3 的 2.37，匹配到更好框的比例从 32.5% 降到 19%。分界在 Decoder 1 到 Decoder 2 之间，与第 11 节分数–IoU 相关在 Decoder 2 最低一致。
3. **重放结果显示了一种可能自我强化的机制，但这里不能证明：** 被匹配的 query 得到正的分类目标，另一个得到 0；分数差变大后，匹配又更偏向它。重放用的是最终权重，只能显示这种结构存在，不能证明训练过程中就是这样逐步形成的。
4. **框监督与分类监督分开：** 并集让一部分更好的框继续学回归，而 MAL 把它当背景，这与第 11 节“更好的框 IoU 上升、分数被压低”一致。
5. 局限：480 对来自 75 张 val 图；只做了重放，没有记录真实训练中的分配；分类代价依赖当前分数，所以“分类代价更高”部分是排序已经错了的结果，不完全是原因。

**判读：** 降低分类代价后，匹配器确实会选择更好的定位候选，而且在 1–0.5 之间几乎不破坏原有的合格匹配，也不影响 MSAR。权重为 0 时虽然几乎全选最佳框，但匹配到的 query 概率中位数只有 .11，正样本会落到模型并不认为是目标的 query 上。这只是离线结果：模型输出固定，不能反映训练中分数和框随之变化后的效果，也不说明 AP 会提高。

### 实验 B：分类与框损失在 query 特征上的梯度

对每层 Decoder 输出的 query 特征 q（256 维），分别计算两个梯度：

- **分类梯度：** 本层 MAL 对 q 的梯度，用本层自己的匹配。
- **框梯度：** 5·L1 + 2·GIoU 对 q 的梯度，用并集。不含 FGL/DDF。

统计只针对框损失覆盖到的 tank query；损失不按 GT 数归一化。

**表 26：梯度余弦与范数（OGSOD）**

**判读：**

1. **没有发现强的负梯度冲突。** 所有组的余弦中位数都在 ±.015 以内，没有一个 query 低于 −.3，两种梯度在共享特征上基本正交。OGSOD 和 MSAR 在这一点上没有差别。
2. **差别在于有没有“分类背景 + 框正”这类 query：** OGSOD 每层有 353 个，MSAR 只有 2 个。但在当前权重下，这些 query 的分类梯度已经很小，因为分数低，MAL 的权重 p^1.5 也小，所以它们实际上主要只受框监督。
3. 局限：这是收敛后 EMA 权重的一个快照。训练早期分数较高时，背景分类梯度可能更大，这里无法观察；FGL/DDF 未计入；余弦只反映 q 这一层，共享参数上的冲突没有测。

### 对实验 C 的影响

- **E1（降低分类匹配代价）：** 实验 A 给出了机制上的支持：选择变化集中在 OGSOD tank，且没有破坏原有的合格匹配。
- **E2（层内对齐的框监督）：** 实验 B 没有找到它要解决的梯度冲突，依据变弱。它仍可能通过别的途径起作用，但不宜作为第一个训练实验。

## 14. 全 SARDet-100K 的排序错位，以及 MAL 的作用（2026-11-08）

E000（`best_stg2`，EMA），Decoder 末层，全部 10,492 张 val 图，22,703 个 GT。

- **候选与排序：** 对类别 c 的每个 GT，候选为在同图 c 类 GT 中与它 IoU 最高、且 IoU ≥ .1 的 query，分数为该 query 的 c 类 sigmoid 分数。“第一名”是分数最高的候选，“最好的框”是 IoU 最高的候选。
- **MAL 正样本：** 末层再用训练 matcher（全部类别 GT）重放一次。被匹配的 query 是这个 GT 在该层唯一的 MAL 正样本，其余 query 的目标为 0。
- **交换 Oracle（不可部署）：** 把最好的框交给第一名，把第一名的框交给最好的那个 query；分数和检测列表（后处理前 300）不变。所以 AP 的变化只反映“把对的框排在第一”的价值，不修重复框，也不修背景。
- 脚本 `tools/sardet100k/ranking_mismatch_survey.py`，结果在 `independent_verify_20261106/ranking_mismatch_survey/`。各组基线 AP 与来源 × 类别评测一致（例如 OGSOD tank 30.66）。
