# D7.1 定位质量信息的可用性：五种信号的竞争对排序

这一轮不训练、不改结构。特征在服务器上用 CPU 提取，排序器在本地 CPU 上拟合；GPU 4、5 继续跑 E008。

## 口径

- **权重与网络层：** E000 第 35 轮 EMA（`best_stg2`），末层 decoder，即后处理实际使用的那一层。E1 第 35 轮只作参照。
- **数据：** val 中的 OGSOD tank；MSAR tank 作对照，OGSOD bridge 作参照。
- **竞争对：** 与 D7 相同。
  - 候选：在同类 GT 中以该 GT 为最大 IoU 对象、且 IoU ≥ .5 的 query。
  - 一对候选中至少一个的最终分数 ≥ .1，两者 IoU 不相等。
  - 标签：IoU 更高的那个 query。
  - 复现检查：E000 OGSOD tank 得到 2,454 对，D7 为 2,456 对；不加权排序正确率 .589，与 D7 的 .591 一致。
- **信号：** 都取自同一次前向，用前向 hook 读出。抽取时断言了 hook 读到的最终 logit 与模型输出一致。

| 编号 | 内容 | 维度 |
|---|---|---|
| S0 | 预测框几何（cx、cy、w、h、log w、log h）。**对照项**：检查结果是否只是“框大小、位置”这类捷径 | 6 |
| S1 | 该类的分类 logit：raw 为 score head 输出；final = raw + LQE，即后处理排序用的值 | 1 |
| S2 | LQE 输出（加到所有类别 logit 上的标量） | 1 |
| S3 | LQE 输入：4 条边各自的 top-4 概率及其均值 | 20 |
| S4 | 末层 box head（`dec_bbox_head`）：第一隐层 h1（256）、第二隐层 h2（256）、输出分布 out（4×(reg_max+1) 个 logit） | 256 / 256 / 132 |
| S5 | 末层 decoder query 特征，即 score head 的输入 | 256 |

- **标量信号**（S1、S2）：直接比较，数值大者为好。
- **向量信号：** 用线性两两排序器 P(i > j) = σ(wᵀ(f_i − f_j))。
  - 不带偏置，两种顺序都参与训练；特征先标准化。
  - L2 系数在训练折内用分组内层交叉验证选定。
  - 外层是按图像分组的 5 折交叉验证：同一张图的所有竞争对都在同一折。
  - 每个 GT 总权重为 1，平均分给它的各个竞争对。
- **Spearman：** 每个 GT 在自己的竞争 query 上计算（至少 3 个），向量信号用折外排序器得分，取各 GT 的均值。
- **95% CI：** 对折外结果做图像级 bootstrap，1,000 次。
- **余弦分档：** 按两个 query 的 S5 余弦分为 < .90、.90–.98、≥ .98。
- **代码与输出：** `tools/sardet100k/quality_signal_probe.py`（extract / analyse）。服务器输出在 `independent_verify_20261106/d71_probe_E000` 与 `d71_probe_E004`，本地在 `analysis_outputs/d71/probe.json`。

## 回答：信息是否已经在网络里？

**两种情况都成立，但程度不同。**

1. **MSAR tank 是天花板，OGSOD tank 离它很远。** MSAR 上除了框几何，所有信号都在 .93–.96，分类 logit 已经用到了全部可用信息。OGSOD tank 上最好的信号（S4 h1）也只有 .646；IoU 差 ≥ .1 的对上是 .726。

   → **网络在 OGSOD tank 上提取到的定位质量信息本身就不足。** 这一点任何“把信息传给分类分支”的改法都补不上。

2. **有一部分信息已经在 box 分支中，但没有进入分类分数：**
   - S4（.646）比 S1（.570）高 .076，两者 CI 不重叠。Spearman 为 .378 对 .168。
   - S4 也明显高于框几何对照 S0（.583，CI 不重叠），所以这部分额外信息不只是框大小、位置的捷径。
   - S5 排在中间（.595）。S5 作线性排序器，在形式上包含了 score head，但只比 S1 高 .025，CI 有重叠。

   → box head 的非线性变换中形成了一些 query 特征里“线性不可读”的质量信息，分类 head 是线性的，读不到。这和你预期的情形一致：S4 能区分，而 S5 和 S1 区分得较弱。

3. **LQE 失效的原因在输入，而不只是量级。**
   - S2（LQE 输出）在 OGSOD tank 上是 .485，处于随机水平。
   - 它的 20 维输入 S3，即使配上专门训练的排序器，也只有 .524，同样接近随机。
   - 同一个 box head 的完整输出分布（S4 输出分布，132 维）却能达到 .644。

   → 质量信息在“取 top-4 概率再求均值”这一步汇总时丢掉了。在 MSAR 上，S3 有 .948，说明这种汇总只在定位分布本来就尖锐、分得开的数据上才有效。

4. **E1 的“特征近似副本”并没有把信息抹掉，是分类头没有用到它。**
   - E1 中 S5 余弦 ≥ .98 的对：S1 是 .500（随机），而对同一批对，S5 线性排序器有 .636，S4 h1 有 .671。
   - 所以即使两个 query 的特征几乎一样，残余差异里仍然有可线性读出的质量信息，只是分类头的权重不朝这个方向。
   - E000 在这一档只有 108 对，结论主要依据 E1。

5. **OGSOD bridge 位于中间：** S1 与 S4、S5 都在 .72 左右，分类头已经用到了可用信息，剩下的差距属于第 1 点所说的提取不足。LQE 在 bridge 上同样偏弱（S2 .558，S3 .634）。

## 对设计方向的含义（结论，不是模块方案）

- **方向 A：让分类分数读到 box 分支已有的质量信息。** 在 OGSOD tank 上，可利用的空间估计约为排序正确率从 .57 提到 .65（S4 的水平），而 LQE 现在的输入在 OGSOD 上不携带这部分信息。这个方向有证据支撑，但上限有限。
- **方向 B：给网络新的定位证据。** 例如目标的局部图像结构；可参考 tank 诊断第 8–14 节对 OGSOD tank 结构的分析。这是缩小与 MSAR（.95）差距的唯一途径，但本轮数据只能说明“需要”，不能说明“从哪里来”。
- **判断：** 只做 A，OGSOD tank 的收益预计有限；A 和 B 是否值得做，要看定位质量排序与 AP75 之间的关系。下一条建议用来量化这一点。

## 局限

1. **样本量：** OGSOD tank 只有 81 张图、910 个 GT，CI 宽度约 ±.03–.04。S4 和 S5 的差（.051）在边界附近：S4 h1 [.616, .678] 对 S5 [.567, .621]，刚好不重叠。
2. **探针形式：** 线性排序器是能力的下界，非线性探针可能读出更多；S1 和 S2 不经训练。所以“S5 中线性不可读”不等于 S5 中没有这部分信息。
3. **捷径对照：** 框几何对照 S0 有 .58–.61，说明框大小和位置本身就带有一部分可以利用的偏向。本轮没有做“S4 在 S0 之外还能增加多少”的联合探针。
4. **训练范围：** 排序器在每个单元格内单独训练，没有检验跨单元格的迁移。
5. **分档样本：** E000 余弦 ≥ .90 的两档各只有约 100 对，不足以单独下结论。

## 下一步建议（CPU 即可，不训练）

1. **联合探针 S0 + S4 对比 S0：** 量化 box head 在框几何之外提供的质量信息，排除捷径。
2. **swap oracle 换算：** 用 S4 的折外排序器得分替代分类分数，只在同一 GT 的候选之间重新排序，其他检测框不动，离线算一次 OGSOD tank 的 AP 与 AP75。这样能把方向 A 的上限换算成指标，用于判断值不值得做。
