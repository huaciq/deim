# BAFR：bin 对齐的分布精修（已放弃，未实现）

日期：2026-11-06。只针对 SARDet-100K。所有数字来自冻结 E000 的分析，没有训练过这个模块，test 未使用。

**结论：不实现。** 下面“aircraft 复核”的增益是用 val 标注训练小头得到的。换成 train 标注训练后，aircraft 上 `aligned` 只比 `query` 高 0.74 AP，低于预先写定的 1 AP，详见“用 train 标注复核”。文档后面的模块设计和判定只作记录。

脚本：`tools/sardet100k/error_budget.py`、`tools/sardet100k/edge_probe.py`。结果在 E000 运行目录的 `independent_verify_20261106/budget/report.json` 和 `edge_probe/`（`report.json`、`report_aircraft.json`、`report_strict.json`、`calibration.json`）。

## 为什么是定位

用真值模拟同样 20% 的改善（这里的基线 AP 是 65.17，因为只保留了分数 ≥0.01 的框，所以看差值）：

| 改善 20% | AP | 增量 |
| --- | ---: | ---: |
| 定位误差 | 71.03 | **+5.86** |
| 其中长边 <16 | 66.77 | +1.60 |
| 其中长边 16–64 | 67.79 | +2.62 |
| 其中长边 ≥64 | 66.69 | +1.52 |
| 漏检 | 65.53 | +0.36 |
| 背景误检 | 65.30 | +0.13 |

另外，按真实 IoU 重排分数的上限是 +4.10（69.27）。

这更正了之前“能改进的部分集中在 16 像素以下”的判断。这些是上限，不是可达值：部分误差可能是标注噪声，下一节也说明大部分定位空间并不能靠小头拿到。

## 机制

D-FINE 给每条边 33 个 bin，每个 bin 都对应边法线上的一个位置：

    位置 = 初始框的边 + W(n) · 框边长 / 4（n 越大越向外）

但这 33 个 logit 都由同一个 query 向量经 MLP 算出，在计算时并没有看过这些位置的特征。检测器的定位信息只能先压进 query。

假设：直接在每个 bin 的位置取特征再算 logit，边缘定位应该更准。

## 零训练检验

冻结 E000，在最后一层分布上加一个小残差头。按近重复组做两折交叉拟合，只在另一折评估。分数不变，只改框。

| 头 | 输入 | AP | AP75 | AP90 | 除 aircraft 的 AP | aircraft AP |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 基线 | | 65.19 | 70.02 | 29.06 | 65.77 | 62.32 |
| `query` | query、当前分布 | 66.45 | 72.77 | 28.56 | 67.42 | 61.62 |
| `roi` | 再加框内池化特征 | 66.36 | 73.09 | 28.35 | 67.19 | 62.20 |
| `aligned` | 再加每个 bin 位置的 S2、P3 特征 | 65.72 | 72.26 | 28.23 | 65.10 | **68.83** |
| `aligned_raw` | 再加对数灰度 | 65.52 | 72.19 | 28.84 | 64.87 | 68.76 |

### 判读

1. **普遍定位的假设被否定。** 预先写定 `aligned` 比 `query` 在 aircraft 之外涨 ≥ +0.5 才通过，实际 −2.32。没有证据说明它能改善 ship、car、tank、bridge、harbor。
2. **`query` 的增益不算方法。** 它主要来自 tank（+4.51）、bridge（+4.00），和已知的 OGSOD 常量偏移一致。这属于标注偏差，已决定不作为研究方法。
3. **对数灰度没有增加信息。** `aligned_raw` 不比 `aligned` 好，这也不支持 RSE 的比值或灰度通道路线（只是冻结检验，不能完全否定）。
4. **aircraft 是例外，这个发现是事后看到的**，所以单独做了下面的检验。

### aircraft 复核

判定标准先于结果写定：严格分折（整图相关 ≥0.6 归同组）、按类单独训练时，`aligned` 比 `query` 高 ≥ 3 AP 才算真信号。

| 头 | aircraft AP | 无超界 GT 的图：AP / AP75 / AP90 | 有超界 GT 的图：AP / AP75 / AP90 |
| --- | ---: | --- | --- |
| 基线 | 62.32 | 65.44 / 65.11 / 29.95 | 56.73 / 59.85 / 14.98 |
| `query` | 62.15 | 65.89 / 73.78 / 22.30 | 55.43 / 58.63 / 10.45 |
| `aligned` | **67.95** | **70.21 / 79.72 / 29.46** | 63.65 / 68.77 / 21.80 |
| 只用 S2 | 67.50 | 69.89 / 80.00 / 28.58 | 62.79 / 68.88 / 21.04 |
| 只用 P3 | 67.79 | 70.13 / 79.76 / 27.85 | 63.47 / 69.29 / 20.79 |

- **通过：** 差值 +5.80。
- **不只是框超出图像：** 没有超界 GT 的图上也涨 4.32。
- **关键是对齐：** `roi` 用相同特征但不对齐，aircraft 基本不涨。
- **不需要高分辨率：** 只用 P3 就够，模块可以不改骨干。
- **改善的主要是大误差：** 长边 ≥64 的边缘误差中位数只从 1.843 变到 1.773，AP75 却明显上升。具体是哪类错误还没有看。

一个可能的物理解释（未检验）：512 图中的 aircraft 是离散散射点，数据集画像里亮连通域中位数 16 个，最大连通域只占 0.48。框的边由机头、翼尖等较弱的端点决定，这些端点的证据在压成一个 query 时容易丢失。ship 多是连续亮块（最大连通域约 0.95），基线本来就准。

### 局限

- 严格分折时最大的组有 5,337 张图，两折不均衡。同一机场相关性较低的切片仍可能跨折，泄漏不能完全排除。
- 按类单独训练时，其他类都变差（ship 73.71→66.00，bridge 45.95→38.10）。ship 样本并不少，所以这不只是样本不足，这个头在这些类上会学坏。端到端训练也可能伤害它们，这是最大的风险。
- 冻结特征不等于端到端效果，结论可能偏高也可能偏低。
- val 的 aircraft 比 test 容易（E000 62.78 对 49.80），val 增益不一定能迁移到 test。

## aircraft 增益是否真实

脚本 `tools/sardet100k/edge_probe.py`（`check`）、`tools/sardet100k/twin_labels.py`、`tools/sardet100k/edge_transfer.py`。结果在 `edge_probe/` 的 `check.json`、`twin.json`、`transfer.json`、`report_check.json`。

### 全局对照（通过）

只看整图全局特征的头，aircraft 62.70，`aligned` 67.95。增益不是靠认出来源或场景得到的。

### RSAR 独立标注（无法判定）

匹配上的只有 44 张图的 436 个框，长边中位数 23，而增益主要在长边 ≥64。这批框上 `aligned` 相对官方框也变差（IoU −0.030），相对 RSAR −0.011（95% 区间 −0.020 到 0.001）。这不是增益所在的人群，所以无法判定。

### 像素相同的 val 和 train 副本

163 张图、395 个框。官方标注在同样的像素上并不一致，两份标注的 IoU 中位数 0.817。

| 范围 | 框数 | 基线到 val 标注 | 修正后到 val 标注 | 基线到 train 副本 | 修正后到 train 副本 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全部 | 395 | 0.814 | 0.836 | 0.880 | 0.836 |
| 长边 ≥64 且两份标注不同 | 215 | 0.779 | 0.820 | 0.881 | 0.822 |

基线明显更接近 train 副本，说明 E000 记住了 train 标注。小头则把框移向 val 标注。预设要求“向副本的增益达到向 val 增益的一半”，实际为负，未通过。这里有一部分是必然结果：两份标注不同时，靠近一份通常就会远离另一份。

### 用 train 标注复核（决定性）

冻结 E000，用 6,000 张含 aircraft 的 train 图及其 train 标注训练小头，在全部 val 上评估 aircraft：

| 头 | AP | AP50 | AP75 | AP90 |
| --- | ---: | ---: | ---: | ---: |
| 基线 | 62.32 | 93.18 | 63.19 | 24.35 |
| `query` | 62.39 | 92.94 | 63.16 | 24.17 |
| `aligned` | 63.13 | 92.51 | 63.44 | 27.63 |

- 预设标准是差值 ≥2 实现，<1 不实现。实际 +0.74，折合全类约 +0.12，不实现。
- val 标注训练时 AP75 涨到约 80，这里只有 63.44。那部分增益主要来自 val 标注，或同一目标的切片跨折，端到端训练拿不到。
- AP90 涨了 3.28，AP50 降了 0.67。这是弱信号，单独不够立项。
- 局限：E000 在 train 上更准（匹配框平均 IoU 0.867），小头的训练样本比真实误差轻，所以这不是彻底否定。

### 目视

修正最大的框，多是基线只框住飞机一部分，修正后扩展到整架，符合离散散射点的解释。但同一架飞机在多张重叠切片中反复出现，修正后的框几乎贴着标注（IoU 0.98），很可能是记住了同一目标。

### 教训

- **只用 val 训练的冻结检验会把 val 标注习惯算成增益。** `docs/sardet100k_baseline_diagnosis.md` 里“看图的头让 aircraft 涨 5.26”用的也是这种检验，可能有同样的问题，不能作为依据。
- **定位 +5.86 的上限大多拿不到。** 它包含标注不一致，aircraft 的官方标注在相同像素上就不一致。

## 同时否定的方向

**按来源校准分数：** 按类别和图像格式、尺寸分组做单调校准，交叉拟合 AP 从 65.17 降到 64.11，同折拟合也只有 64.29。bridge 从 45.95 降到 41.26。排序的 +4.10 上限拿不到这部分。

## 模块设计

```text
最后一层解码器：query → 原 FDR 头 → 33 个 logit（四条边）
                                      │
P3（encoder 输出，256 维）            │
  │ 在每条边、每个 bin 的位置采样      │
  │ （沿边方向 3 个点取平均）          │
  ▼                                   │
1×1 投影 → 三层空洞 1D 卷积（d=1,2,4） │
  ▼                                   ▼
每个 bin 的残差 logit × 门控 γ ──────→ 相加 → 积分得到框 → LQE、FGL、DDF
```

1. **位置：** 只作用于最后一层解码器（`engine/deim/dfine_decoder.py:672`，`bbox_head` 之后、积分之前）。
2. **采样：** 位置由 `ref_points_initial` 和 W(n) 算出，框停止梯度。bin 顺序统一为向外，四条边共享卷积，只用边嵌入区分。
3. **上下文：** query 和边嵌入经 MLP 后加到每个 bin 上。
4. **门控：** γ 由 query 和类别概率算出，每条边一个值，最后一层零初始化，所以起点等于基线。这是为了应对其他类被学坏的风险，也是消融要检验的一点。
5. **损失：** 不加新损失，沿用 FGL 和 DDF。修正后的最后一层也是 DDF 的教师。
6. **超参数：** 沿边 3 个点，卷积宽度 128（与检验一致）。不设新的损失权重。
7. **代价：** 参数约 0.35M（估计，占 19.48M 的约 2%）；每图约 12 万次 `grid_sample` 采样。显存和速度的影响未测。

## 为什么和已有工作不同

- **最接近的是 SABL**（我的记忆，这轮检索没有核对原文）：两阶段检测里按边分桶定位。这里是在 DETR 的分布回归里把 bin 和位置一一对应。
- **D-FINE：** 按边建模分布，但检索结果没有显示它在 bin 位置取特征。
- **SAR 检测里的边缘模块：** 检索到的多是把边缘特征融进 FPN，或改回归损失。
- 只查了两次，不能证明没有相同工作，投稿前要再查。

## 判定

| 项目 | 内容 |
| --- | --- |
| 协议 | 与 E000 相同，36 轮，seed 0；只看 val |
| 主指标 | val AP 比 65.29 涨 ≥0.5；不到 1.0 时补基线和方法的第二种子 |
| 机制指标 1 | aircraft AP 涨 ≥2，且无超界 GT 的图上 AP75 也上升 |
| 机制指标 2 | 其他五类的平均 AP 降幅不超过 0.3 |
| 证伪 | aircraft 不涨，或其他类的损失抵消增益 |
| 消融 | 去掉门控；框内池化代替对齐；只加 query 残差头 |

主观估计（没有实验依据）：涨幅 ≤+0.3 约 40%，+0.3–1.0 约 40%，+1.0–2.0 约 17%，>2 约 3%。冻结检验中，只算 aircraft 的增益折合全类约 +0.9–1.1。

## 局限

- 主要受益的只有 aircraft 一类，不解决 tank、bridge 的问题。
- 单独写成论文的卖点偏窄，更适合作为 GREA 的定位侧搭档，前提是 GREA 有效。
- 实现前要先看一下 aircraft 上到底修好了哪类框。
